# Sage Vista 产品决策日志

本文件记录产品方向与用户要求。实验数字和因子结论仍以 `research/experiments.jsonl` 为机器账本。

## 2026-08-29：因子研究回到“长期上涨后的回调买入”

- 最大赢家高ATR等共性主要是收益尾部描述，不再作为选股优化主线。ATR只用于把回调、止损和仓位换算到统一风险尺度，方向权重为0。
- 个股、大盘和行业ETF统一研究“长期趋势仍在 → 可控回调 → 支撑保持／抛压减弱 → 日线MACD等证据确认修复”，三层结果和贡献继续分开。
- MACD柱三日增强、回调深度和持续时间、缩量、上下跌日量比、相对强弱保持、RSI重回50与金叉质量进入候选总表；未验证前只积累，不提高正式权重。
- 赢家／输家V1失败的五项临时权重不拆开上线；旧因子的原始数值可以在新条件问题中重新研究，但必须建立新实验版本。

## 2026-08-29：建立可复用因子策略实验室，不再靠极端样本讲故事

- 外部因子发现优先参考有明确公式和开源实现的项目；首批来源锁定 Microsoft Qlib、QuantConnect Lean 与 `ta`，每个候选保存来源、公式、输入、家族、与现有因子的重叠及生产权重0。
- 外部公式必须翻译成 Sage Vista 的条件问题：长期趋势是否干净、回调是否新鲜且伤害有限、回调是否仍在吸筹、MACD金叉是否发生在低噪音和真正修复背景；不能为了“因子多”照搬指标。
- 最大赢家第一名、第二名只生成案例卡供人工复核，不能以两只股票决定权重。正式差异来自年度内前10%赢家与同季度、相近旧分、前20日动量、60日回撤和ATR的失败样本配对，并同时保留全部命中/未命中对照。
- 新候选先在历史回溯式走步中逐段冻结方向和阈值，再做后段检验；2025和2026已经被看过，只能作为已见期复核。锁定日之后的新交易日才构成真正未见前向。
- 实验自动输出保留研究、观察、淘汰和样本不足；同家族最多一个候选进入未来权重挑战者。任何候选都不能因单个极端赢家或一段历史表现直接改变生产评分。

## 2026-08-29：建立独立行业研究总表

- 以后行业研究不再依赖临时口头列举；`docs/INDUSTRY_RESEARCH_UNIVERSE_ZH.md` 集中保存全部研究主题、参考ETF、数据状态、产业链分组和启动顺序。
- AI与科技不能混成一个模糊主题，至少分成综合软件、云计算、网络安全、AI软件、半导体、内存存储、机器人、AI基础设施、半导体设备和数据中心电力。
- 主题注册表v3增加IGV综合软件官方来源，并登记AI软件与应用、内存与数据存储为人工审核主题；没有带日期成员证据前不猜成员。
- 独立行业研究获准作为未来研究线；行业ETF长历史与带日期成分股前向必须分开，未经验证的行业结果不写入技术分。

## 2026-08-29：研究从旧因子审计转向赢家／输家驱动的策略优化

- 在完整日线MACD刚金叉候选池中，先保存开发期收益最高100个赢家和最低100个输家，寻找现有因子与连续价格、趋势、位置、动能、量能、波动、K线特征的差异。
- 最大100只用于发现和人工复核，不能单独决定权重；实际晋级同时要求全部前后10%富集、开发期内部校准、跨年度方向和稳健收益一致。
- 2001—2018用于发现候选与阈值，2019—2024用于开发期内部校准；2025只作独立验证，2026只作前向观察，不得用验证或前向结果重新挑阈值。
- 新权重先形成独立整数权重挑战者，按因子家族去重和封顶；未通过成本后期望、PF、样本量和极端值检查前，不覆盖生产模型或重写旧事件。
- 技术特征负责技术挑战者。大盘单独报告；缺少历史时点股票—行业成员关系时，行业维度明确不可用，只使用行业ETF独立实验与2026之后的带日期前向关联，不拿今天的分类回填历史。
- V1已完成但没有通过独立检验：开发期冻结的5项整数权重在2025与2026均降低共同门票的成本后期望和PF，不升级生产评分，也不把看起来反直觉的临时方向包装成结论。
- 最大赢家的高ATR、MACD柱加速、强趋势和远离均线主要描述“收益弹性”；它们可能同时放大赢家与输家。下一版策略优化必须把“上涨概率／可靠性”与“收益弹性／尾部潜力”分成两轴，不能继续塞进一个总分。
- 极端100受行情制度影响很大：最低100中59个发生在2020，另有接近归零的旧代码事件需要公司行动、退市和代码变更审计。极端样本保留，但不直接决定权重。

## 2026-08-29：每日行情不再只依赖 GitHub 定时器

- 现有自动记录证明 GitHub schedule 虽会产生运行，但实际触发可延迟数小时；启用以来当天首次数据发布仍由人工任务完成，不能再把它视为可靠主时钟。
- Cloudflare Cron 作为独立主触发源，调用同一条 GitHub 日终生产工作流；GitHub schedule 仅作备用，不能继续充当唯一启动机制。
- 新鲜度检查也由独立调度源触发；发现网站落后于数据源时，必须自动 dispatch 一次幂等日终更新，再失败才创建告警。
- 外部调度只能使用限定到本仓库 Actions 写权限的独立令牌；不得复用个人广权限登录令牌，也不得把令牌写入仓库、日志、普通变量或网站产物。
- 每次日终结果记录触发来源；重复触发继续以 `already_current` 安静退出。自动化修复不改变行情日期、防前视、MACD门票、评分、排名或通知闸门。

- 所有语义改动必须先总结用户意图、更新并版本化对应规则，再改代码；纯修错和重构也先记录范围及“不改变业务语义”。
- 每个完成项写回规则版本、实验 / 数据产物、测试、提交和生产验证；只有本地代码不算完成。
- 当前进度文档由生产、回测、因子和实验机器状态生成，并随相关自动任务更新，避免人工交接再次过期。

## 2026-08-28：退出风险分 V0 与三段 RSI 背离

- 退出风险分与入场排名完全分开：实体看跌吞没先记 2 分，紧接阴线继续收低附加 1 分，三峰 RSI 顶背离记 1 分，MACD 正柱连续缩短记 1 分。
- 退出分初始最高 5 分；2 分与 3 分两个门槛都在回测前固定比较。当前只做影子研究，不能冒充已验证卖出规则。
- 硬止损不参与累计分，命中后直接执行。
- 三个更低价格低点而 RSI 依次不再创新低，登记为入场端三段 RSI 底背离；强于普通两段底背离，但同组取高、不重复相加。
- 所有分值均是可被回测推翻的主观先验；以后只能通过新实验版本调整，不能重写旧实验。

## 2026-08-28：评分与退出机制分离

- 入场评分只负责选择机会，不能作为持仓不退出的理由。
- 入场后的风险与退出条件由独立机制持续检查；已经验证、批准并启用的条件触发后，按最早可执行时点退出。
- 周线 / 月线机会可以拥有更长研究窗口，但不能放宽结构止损、最大风险或拖延明确退出。
- 新退出机制先做单一变量回测并冻结版本，未验证前不直接改生产执行。

## 2026-08-28：退役旧个股研究与预登记周期评分 V3

- 删除旧“个股研究 / MACD Tracker”页面与导航；它是过时的独立排名产品。多因子机会成为唯一排行榜并承接个股详情。
- 新评分挑战者保持日线 MACD 为门票，但不再用所有候选共同命中的门票制造排序差异。

- 主导周期由日 / 周 / 月去重贡献决定；周线或月线标签至少需要两个独立证据组，且必须包含方向、动能质量或结构证据。
- 排行榜和个股详情显示周期标签与分项贡献；标签当前只描述机会来源，建议持仓时间需按周期完成独立回测后再批准。

## 2026-08-28：总规则手册与先文档后代码

- 建立 `docs/SAGE_VISTA_RULEBOOK_ZH.md` 作为精简的项目宗旨、全局流程和模块地图；具体规则拆分到 `docs/rules/` 的独立模块，改评分只改评分规则，跨模块改动才联动相关文件。
- 项目宗旨固定为：积累技术面与基本面交易经验、用机械化规则减少情绪、先成为实用选股器、通过回测和前向跟踪寻找有效多因子组合，并最终交付直接可用的网站。
- 经过验证的有效打法进入 `11_VALIDATED_PLAYBOOK.md`；由实验或真实损失确认的严格禁区进入 `12_HARD_RULES.md`。成功和亏损教训都必须成为长期规则，不只留在聊天中。
- 总原则固定为“大周期看方向，小周期找时机”：日线 MACD 负责触发；同类因子月线优先于周线、周线优先于日线；周期主导决定主要评价与最长持仓研究窗口。
- 实验必须预登记、按周或日期块保存、可从断点继续，并永久保留配置、进度、结果、失败和样本不足结论；网站必须解释实验做什么、结果多少、能不能用和怎样使用。
- 后续语义改动固定为：先更新并版本化规则 → 追加决定 → 预登记实验 → 改代码与测试 → 回测和留档 → 更新 UI → 部署并核验。
- 根目录新增 `AGENTS.md`，要求后续 Codex 对话先读精简总手册，再只读取受影响模块及联动文件，并区分当前实现、目标规则和尚未实现内容。

## 2026-08-25：Early Watch 与 GitHub Actions 自动化

- Early Watch 只接受尚未金叉、日线负 MACD 柱至少连续两根收缩、MACD/Signal 差距单日缩小至少15%、已经进入 near-cross 区域，并至少获得两项独立证据支持的股票。
- Confirmed 接受随后五个交易日内完成且仍有效的日线金叉并通过现有 MACD 买入门槛，或达到多因子雷达5分门槛的股票。
- Discord 状态按股票持久化：相同状态不重复，Early Watch → Confirmed 允许再提醒，Confirmed 不允许降级回 Early Watch 重发。
- GitHub Actions 在美股交易日后的三个 UTC 时段重试 EODHD；数据未准备好、日期不一致、扫描失败、future-data 异常、测试失败或构建失败均停止，不提交公开 JSON。
- 定时 update job 只做 preview，不直接发送。现有私有 Sites 仅在 Sites API 确认发布成功后创建 GitHub Deployment success 记录；notify 必须核对其 ID、EOD 日期、站点 URL 和仓库审计状态，网站未更新时 Discord 必须停止。

## 2026-08-25：支撑位量价确认因子

- 新增两个候选观察因子：支撑位底部放量、支撑位看涨吞没，各记观察分 +1，不进入正式分。
- 两项必须与已登记支撑背景紧密绑定；当前支撑背景包括 Fibonacci、EMA、Bullish FVG、三推突破回踩，以及只作位置判断的 Volume Profile／K线聚集区。没有支撑背景时不计分。
- 支撑位底部放量精确定义：价格位于60日区间下方45%，完整日成交量至少为此前20日均量的1.5倍且高于前一日。
- 支撑位看涨吞没精确定义：前一根为阴线，最新完整日K为阳线，阳线实体完整包住前一根阴线实体。
- 两项来自用户经验假设，后续必须单独记录样本、防前视结果和跨时期稳定性；失败或样本不足结论永久保留。
