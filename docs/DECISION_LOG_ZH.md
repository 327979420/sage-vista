# Sage Vista 产品决策日志

本文件记录产品方向与用户要求。实验数字和因子结论仍以 `research/experiments.jsonl` 为机器账本。

## 2026-08-28：总规则手册与先文档后代码

- 建立 `docs/SAGE_VISTA_RULEBOOK_ZH.md` 作为精简的项目宗旨、全局流程和模块地图；具体规则拆分到 `docs/rules/` 的独立模块，改评分只改评分规则，跨模块改动才联动相关文件。
- 项目宗旨固定为：积累技术面与基本面交易经验、用机械化规则减少情绪、先成为实用选股器、通过回测和前向跟踪寻找有效多因子组合，并最终交付直接可用的网站。
- 经过验证的有效打法进入 `11_VALIDATED_PLAYBOOK.md`；由实验或真实损失确认的严格禁区进入 `12_HARD_RULES.md`。成功和亏损教训都必须成为长期规则，不只留在聊天中。
- 总原则固定为“大周期看方向，小周期找时机”：日线 MACD 负责触发；同类因子月线优先于周线、周线优先于日线；周期主导决定主要评价与最长持仓研究窗口。
- 实验必须预登记、按周或日期块保存、可从断点继续，并永久保留配置、进度、结果、失败和样本不足结论；网站必须解释实验做什么、结果多少、能不能用和怎样使用。
- 后续语义改动固定为：先更新并版本化规则 → 追加决定 → 预登记实验 → 改代码与测试 → 回测和留档 → 更新 UI → 部署并核验。
- 根目录新增 `AGENTS.md`，要求后续 Codex 对话先读精简总手册，再只读取受影响模块及联动文件，并区分当前实现、目标规则和尚未实现内容。

## 2026-08-27：旧评分过渡、永久追踪池与实验保全

- 当前生产继续使用旧观察评分和既有门槛；27 因子实验观察分先 shadow monitoring，完成历史回测、独立验证和前向观察后才能以新 signal definition 替代旧评分。
- 达到当时生产门槛即永久进入 Tracking Pool，不要求当前 `official_score > 0`。掉榜只改变状态，不删除；reset 后重新触发建立新案例。
- 因子技术时效与研究状态分开：`ACTIVE / RECENT / EXPIRED / NEVER / UNAVAILABLE` 不得被“不计正式权重”替代。
- Signal History 逐日保存价格、旧生产分、正式分、27 因子实验分和因子时效；Industry/Market 待模块优化后再接入逐日案例。
- Git 历史审计找到 27 个旧 Rare signal-day、18 只股票，PG 于 2026-08-25 以旧分6首次触发。恢复必须保留原始提交证据，不能用当前规则重算。
- 历史实验全部进入永久机器目录；成功、失败、不稳定和样本不足均保留。Historical Backtest 与 Production Forward 同页对照、分别统计。

## 2026-08-27：Market Context 纳入统一生产日更

- `market-etf-watch.json` 不再是独立、可滞后的静态文件；它与 Tracker、factor snapshot、Rare、Industry 和 Signal History 使用同一个权威交易日并原子发布。
- 17只必需 ETF 任一缺少权威日期的完整 bar，整次发布失败关闭；所有输入先裁切到 `as_of`，输出记录 `future_data_used=false` 与完整审计。
- 当前五项旧市场温度评分保持不变，避免未经回测修改生产语义；新增趋势、广度、风险偏好三层结构，只作为决策 context，不回写股票技术分。
- freshness monitor、线上整组验证和 GitHub 日更提交全部纳入 Market Context 文件与日期。

## 2026-08-27：Industry Context V2 数据完整性门槛

- 成分股必须有与 Radar `as_of` 完全一致的完整日 bar；旧价格不得冒充当日行业状态，未来行继续在计算前裁切。
- Theme 除至少5只有效成员外，还必须达到50%有效成员覆盖率；大型篮子不能再由少数可用股票代表整体行业。
- 输出新增 `valid_member_ratio`、`state_model=industry-state-v2`、完整审计和 `decision_context_not_technical_score` 边界。
- Leadership、Pullback、Recovery 阈值暂不按收益优化；先保证 membership 和价格样本可信，再进入预注册分层回测。

- 正常 daily workflow 是唯一发布链：EODHD → 原子生成并提交 public JSON → tests/build → Cloudflare Worker deploy → 对同一 Worker 执行整组 live verification → Discord。
- 删除旧 `sage-vista-sites` deployment attestation 与人工 `notify` job，避免出现两个互相独立的“线上成功”来源。下述 2026-08-25/26 Sites/parallel 记录只保留为历史，已由本决定取代。

- 保留现有 ChatGPT Sites，不删除、不覆盖、不迁移域名。
- GitHub scheduled EOD 只有在产生新数据，或检测到尚未完成的 production state 时，才执行测试、vinext build、Cloudflare Workers 发布、线上日期/未来数据审计与 Discord send。

## 2026-08-25：Early Watch 与 GitHub Actions 自动化

- Early Watch 只接受尚未金叉、日线负 MACD 柱至少连续两根收缩、MACD/Signal 差距单日缩小至少15%、已经进入 near-cross 区域，并至少获得两项独立证据支持的股票。
- Confirmed 接受随后五个交易日内完成且仍有效的日线金叉并通过现有 MACD 买入门槛，或达到多因子雷达5分门槛的股票。
- Discord 状态按股票持久化：相同状态不重复，Early Watch → Confirmed 允许再提醒，Confirmed 不允许降级回 Early Watch 重发。
- GitHub Actions 在美股交易日后的三个 UTC 时段重试 EODHD；数据未准备好、日期不一致、扫描失败、future-data 异常、测试失败或构建失败均停止，不提交公开 JSON。
- 定时 update job 只做 preview，不直接发送。现有私有 Sites 仅在 Sites API 确认发布成功后创建 GitHub Deployment success 记录；notify 必须核对其 ID、EOD 日期、站点 URL 和仓库审计状态，网站未更新时 Discord 必须停止。

## 2026-08-25：支撑位量价确认因子

- 新增两个候选观察因子：支撑位底部放量、支撑位看涨吞没，各记观察分 +1，不进入正式分。
- 两项必须与已登记支撑背景紧密绑定；当前支撑背景包括 Fibonacci、EMA、Bullish FVG、三推突破回踩，以及只作位置判断的 Volume Profile／K线聚集区。没有支撑背景时不计分。
- 支撑位底部放量精确定义：价格位于60日区间下方45%，完整日成交量至少为此前20日均量的1.5倍且高于前一日。
- 支撑位看涨吞没精确定义：前一根为阴线，最新完整日K为阳线，阳线实体完整包住前一根阴线实体。
- 两项来自用户经验假设，后续必须单独记录样本、防前视结果和跨时期稳定性；失败或样本不足结论永久保留。

## 2026-08-25：日线 MACD 金叉五日有效窗口

- 多因子雷达新增候选观察因子“日线MACD近5日金叉”：从触发日开始计五个完整交易日，且当前 MACD 线仍须高于信号线。
- 该因子计观察分 +1，不进入正式分；现阶段来自用户交易经验假设，后续仍须执行单因子、组合、防前视和跨时期验证。
- 雷达不再要求候选只能在金叉当天出现；五日窗口过期或期间重新死叉后立即失效。
- UDR 的数据确认结果为 2026-08-24 收盘金叉；2026-08-20 和 2026-08-21 仍是接近金叉但尚未实际交叉。此前 MACD 显示 0 分，是因为日线金叉被当作资格条件而未进入七项观察分。

## 2026-08-25：日终数据新鲜度改为失败关闭

- SPY 的小型 EOD 查询作为“数据源最新完整美国交易日”的权威日期；MACD、雷达和批量文件必须精确命中同一天。
- 批量接口未就绪、超时或日期不符时禁止静默回退，不替换公开结果，也不部署网站。
- 网站所有保留功能页统一读取 `update-status.json`，显示最新完整收盘日、同步状态及最后成功更新时间。
- 自动任务改为墨尔本工作日 10:15、11:15、12:15 三次收盘后检查；已是最新则安静退出，最后一次仍滞后则明确失败。
- 更新命令统一为 `python3 -m services.scanner.daily_tracker_update`；先生成临时结果，日期与防前视审计全部通过后才原子替换 MACD、雷达和状态文件。

## 2026-08-25：动态组合原则与三推回踩因子

- 用户的市场经验可以先作为因子研究假设；进入观察层不再要求因子单独或仅与 MACD 组合时必须显著提高胜率，但机器规则、防前视和永久记录仍是硬要求。
- 新增 `structure.trendline_three_push_retest`：必须先有有效三推下降趋势线突破，并在其后 10 个完整交易日内触及原趋势线附近、没有实质跌穿且收盘守在线上。
- 三推突破计 1 个观察分，满足依赖关系的回踩确认再加 1 个观察分；两者属于同一 `trendline_breakout` 证据链，UI 必须明确依赖关系。
- 动态因子允许按实际命中自由排列组合，不要求所有候选都凑满固定数量才显示；强依赖因子必须先满足父因子，失败或待测试因子不得进入正式分。
- 多因子雷达新增统一因子库板块，公开展示已登记因子的类别、状态、周期和计分模式，方便用户与后续 AI 复查。

## 2026-08-25：多因子雷达视觉系统

- 多因子雷达优先从文字列表升级为研究仪表盘：总分使用环形图，分类得分使用进度条，命中证据、未命中和风险分区显示。
- 七个证据类别使用稳定的类别色与简洁图标：基础资格、MACD、支撑、价格结构、RSI、量能、风险／供给必须一眼可区分。
- 产品主色从高饱和绿色收敛为深海军蓝、石板灰和低饱和辅助色；绿色不再作为大面积主题色，只在确有“通过”语义时少量使用。
- 移动端保持单列信息顺序，图形不得替代文字含义；颜色、图标和文字需要同时表达状态，避免只靠颜色判断。

## 2026-08-25：Discord 第一版通道入口

- 第一版选择 Discord Webhook；模板必须集中、可替换，不能把当前消息版式视为最终形态。
- 每日播报优先发送5分或以上的多因子雷达股票，随后发送同一数据日的 MACD 看涨与看跌榜。
- Discord 只读取网站同源 JSON；日期不同步、防前视异常、测试失败或网站部署失败时不得发送。
- 去重必须覆盖同一股票、同一日期、同一证据与分数，以及同一日期的相同 MACD 排名；部分内容已经发送时不得借其他榜单变化重复发送旧信号。
- Webhook 只允许保存在被 Git 忽略的本地 `.env.local`，不得进入仓库或 Sites 公开文件。正式配置前先预览消息。
