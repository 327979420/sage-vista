# 01｜执行与文档维护

版本：`1.5.0`
最后更新：2026-09-07

## 本文件负责

这是唯一执行流程。按用户本轮要求合并重复说明，替代旧的全量必读、每项修改先交完整设计包及重复批准要求。业务参数仍归各模块规则；此整理不激活任何候选策略或改变既有生产授权。

## 用户体验与实用性交付准则

1. 每轮确定一个可观察的业务成果，并说明完成判据；文档维护任务以删除重复、消除冲突和引用有效为判据。
2. 只做直接支持该成果的工作。额外框架、文档、角色和非阻断修复进入待办，不作为交付前置。
3. 连续两个工作包没有产出或解除具体阻塞，就检查路线，缩小范围或改用已有能力；不能默认再加一层基础设施。
4. 开工确定合理的资源检查点；默认一次针对性审核，修复后只复核受影响问题。扩大测试须有新证据；不编造 token 数字，不以预算到期冒充完成。
5. 已授权目标内自主完成实施、相关修复和必要验证，不逐包申请批准。未决的重大业务选择、范围扩张、外部成本及生产操作按实际授权处理；需要询问时先完成不依赖答案的工作。

## 一次改动怎样完成

- 在现有 `../CHANGE_REQUESTS_ZH.md` 对应条目简记目标、范围和验收；不要为普通改动新建设计、交接、验收三份文件。碎片想法标为 `captured`，不自动实施；用户明确要求执行且范围清楚即可开始，不强制另一轮批准。
- 改变业务定义时更新对应模块规则，这一步必须发生在代码编辑之前；影响选股、评分、持仓或退出的研究按 `08_BACKTEST_AND_EXPERIMENTS.md` 预登记。纯修错、重构或性能优化只记录必要差异，不无故升级无关模块版本。
- 复杂迁移或真正未决的业务选择才需要简短方案，写在同一条目；仅在现有授权不足时等待决定。已获批范围内部的实现细节不构成新审批。
- 验证受影响行为及数据真实性、防未来数据、历史完整性等实际风险。文档维护检查链接、冲突和相关既有检查；不因此运行无关前端构建或全量回测。
- 将适用的测试、提交、网站证据写回需求账本。文档或本地任务不以部署为完成条件；本地完成、已提交、已上线分别说明，未发生的步骤不得宣称完成。

## 必须保留的业务保护

- 不使用未来数据，不伪造完整股票池、数据来源、授权或已验证收益；formal 缺失不暗中降级为 legacy。
- 历史信号、旧版本及成功、失败、负结果、样本不足、中断实验保留，不静默覆盖。
- 同一业务事实使用唯一计算入口与合同验证入口；技术分、大盘、行业事实分别保存。排行榜是唯一权威顺序。
- 不把合成、本地或旧日期产物称作最新线上结果；实验结论不自动激活生产策略。外部通知必须有明确授权。

## 文档只维护一处

| 内容 | 唯一维护位置 |
| --- | --- |
| 怎么执行、何时询问、如何验证 | 本文件 |
| 产品目的与模块路由 | `../SAGE_VISTA_RULEBOOK_ZH.md`；索引只提供链接 |
| 当前日期、版本、断点 | `../CURRENT_STATUS_ZH.md` 及其机器来源，不手抄到介绍页 |
| 具体业务定义 | 对应 `02`—`12` 模块规则 |
| 本次任务进度和交付 | `../CHANGE_REQUESTS_ZH.md` 对应条目 |
| 历史决策、设计、验收与研究证据 | 原路径按需查阅，不加入默认必读列表 |

用户最新明确指令和授权优先；业务语义查对应模块，实际运行状态查机器产物。发现冲突只核对当前受影响部分，不发起全仓库审计。旧设计中的执行步骤仅供历史追溯，不覆盖本文件；具体业务约束和未批准状态仍保留。

普通修改不再同步多份入口、总手册及决策日志。只有产品目的或模块职责变化才修改总手册；需长期保留的重大决定才追加决策日志。旧链接可保留短跳转页，不再维护第二份正文。删除历史文件前检查引用；本次不批量删除历史证据。
