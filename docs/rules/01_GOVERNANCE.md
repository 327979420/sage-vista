# 01｜规则治理与改动流程

版本：`1.0.0`
最后更新：2026-08-28

## 本文件负责

文档权威、版本、批准状态和从规则到生产的固定流程。不负责具体评分或交易参数。

## 权威顺序

对应模块规则 → 总手册 → 决策日志 → 注册表 / 实验账本 / 版本产物 → 代码与测试 → UI → 聊天。

## 语义改动固定流程

1. 修改受影响模块的规则、版本和变更记录。
2. 在 `docs/DECISION_LOG_ZH.md` 追加日期、理由、范围和状态。
3. 影响选股、排序、持仓或退出时，按 `08_BACKTEST_AND_EXPERIMENTS.md` 预登记。
4. 修改共享底层代码，禁止另建平行口径。
5. 运行单元、防前视、数据契约和网页测试。
6. 分块回测并保存断点；永久保存成功、失败和中断结果。
7. 证据足够后才升级正式权重和 UI 结论。
8. 发布、核对线上版本与数据日期，再报告用户。

安全或未来数据问题可以先暂停生产，但恢复前必须补文档与测试。

## 状态标签

- `current`：当前代码和生产都已实现。
- `approved_target`：规则已批准，但尚未完整实现或验证。
- `experimental`：只允许研究、归因或同分比较。
- `validated`：达到预登记标准并获准进入正式模型。
- `retired`：停止用于新结果，但历史记录永久保留。

任何文档必须区分这些状态。禁止把目标或排队任务写成“已完成”。

## 版本规则

- 模块内部参数变化：只升级该模块版本。
- 模块职责或全局流程变化：同时升级总手册。
- 因子库、评分模型、执行模型、实验、UI 和数据快照分别有版本。
- 历史信号保留当时版本，不用新规则重写旧分。

## 联动条件

治理规则改变时联动总手册和根目录 `AGENTS.md`。普通单模块改动无需修改本文件。
