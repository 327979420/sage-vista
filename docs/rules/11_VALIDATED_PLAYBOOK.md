# 11｜有效策略宝典

版本：`1.1.0`
最后更新：2026-09-05

## 本文件负责

只收录经过开发、独立验证和前向观察后获准使用的因子组合、交易方案与适用条件。它是“目前有哪些打法真的可以用”的答案。

M11的设计状态、机器合同和生产边界见`../M11_STRATEGY_PROMOTION_GATE_DESIGN_ZH.md`。当前规则更新只冻结升级闸门，不新增有效策略。

## 四条状态轴

- 机器证据：`candidate / evidence_incomplete / not_validated / validated / invalidated`；
- 用户决定：`not_requested / approved_for_implementation / rejected / deferred`；
- 实现：`not_implemented / implemented_in_main`；
- 生产：`inactive / active / retired`。

四轴不得合并。验证通过不等于用户批准，批准不等于实现，进入main不等于生产active。

## 收录门槛

- 引用已完成且不可变的实验 ID、规则版本、代码提交和数据范围。
- 达到实验预登记的样本量、收益、回撤、成本和跨时期稳定性标准。
- 明确适用股票池、市场环境、周期、入场、止损、目标、持仓窗和失效条件。
- 写清怎样使用，不把历史胜率保证成未来收益。
- 经用户批准后才从候选观察升级为正式宝典条目。
- 逐项满足冻结的预登记标准；必要证据缺失、结果失败或案例角色混用时不得写`validated`。
- 至少包含一个未参与规则定义／调参的独立validation或真实forward分区，并完成预登记要求的全部必需分区。
- 生产active还必须引用精确实现提交和M12 Manifest、部署及线上核验证明。

## 当前已验证条目

**暂无。** 当前 V2 与新增高周期规则仍处于研究 / 前向观察阶段。旧系统表现可作为基线证据，但在完成统一口径验证前不冒充正式结论。

## 维护规则

新证据推翻旧打法时不删除原条目，改为 `retired`，记录停止使用日期和原因。

定义、阈值、基线或适用范围改变时建立新策略版本；新证据成熟只追加评估修订。发现／校准案例不能在同一版本中改标为独立验证，失败和负结果不得删除。
