# 08｜回测与实验规则

版本：`1.7.2`
最后更新：2026-08-29

## 本文件负责

实验怎样提出、运行、续跑、判断、留档和转化为可用规则。目标是每次实验都产生可复用证据，不白做。

长期回放采用“自然周原始检查点＋年度压缩档案＋永久年度充分汇总”的三层留档。网站不承载逐笔历史，只在整个预注册时期完成后发布总体、五年分段、独立验证、前向观察和可执行层级。原始平均收益若被公司行动或数据极值污染，必须同时报告并优先使用胜率、中位数和分段方向，不能用异常均值晋级因子。

## 实验生命周期

问题 → 预登记 → 基线与唯一改动 → 分块运行 → 独立验证 → 前向跟踪 → 人话结论 → 永久归档 → 进入策略宝典、交易红线或继续观察。

## 运行前必须预登记

每个实验写清：

- 唯一 ID、规则 / 代码 / 数据版本、日期和负责人；
- 研究问题、精确机器定义、父子依赖和冗余处理；
- 股票池、退市处理、流动性门槛和数据范围；
- 触发器、基线、唯一改变项和对照组；
- 开发期、独立验证期与前向观察期；
- 入场、止损、止盈、最长持仓和同 K 线冲突口径；
- 评价窗口、交易成本敏感度、通过与不通过标准；
- 已知限制，包括幸存者偏差、样本量和历史分类缺失。

## 必须可分块、可续跑

- 长任务按自然周或明确日期块运行；每块结束立即保存配置、进度和结果。
- 中断后从最后成功日期继续，不能每次从零开始。
- 新增触发后附加因子时复用已有 MACD 事件池与缓存。
- 只有触发器、股票池、价格调整或数据定义改变时，才重建相应范围。
- 每块记录起止日、股票数、事件数、状态、代码提交与数据指纹。
- 超时只终止当前块，已完成块仍可汇总使用。

## 夜间历史续跑

- 夜间任务按墨尔本时间每天约 21:30（夏令时约 22:30）自动启动；只要数据 Token 可用、任务没有被人工停用，就从断点继续。
- 每晚只回放断点之前的一个自然周。当前已保存区间是 2026-05-01 至 2026-08-27，所以下一批固定为 2026-04-27 至 2026-04-30，之后继续逐周向前。
- 权威断点保存在 `automation/backtest-state.json`，给网站读取的同源进度保存在 `public/backtest-progress.json`。断点只有在周结果生成、校验、合并、全量测试和提交全部成功后才向前移动。
- 每个成功周必须先保存独立周结果，再合并入 `public/unified-v2-rankings.json` 和永久机会账本；中断后重试同一周，不从全部历史重新开始。
- 已完成日期冻结当时的模型、因子注册表和规则版本。新增因子或规则只用于尚未运行的新周；如果以后需要用新规则重算旧周，必须另开迁移实验，不能覆盖原实验。
- 缺少 Token、被人工停用或已经到达目标起点时安静跳过，不伪造进度。夜间历史任务与每日最新收盘扫描相互隔离。

## 科学性底线

- 历史选择只读 `as_of` 及以前数据；周月线只用完整周期。
- 信号收盘确认后，最早下一可交易开盘入场。
- 同一日同时碰止损与止盈时按保守口径先算止损。
- 原始收益、固定持有、支撑止损、2R 和其他策略分别报告。
- 尽可能包含退市股票；做不到必须披露幸存者偏差。
- 至少比较无成本、20bps、50bps；不得只展示理想成交。
- 参数不能根据测试集反复挑最好看结果；需要新假设就新建实验。

## 下一轮因子发现方向（approved design, not started）

- 不再以最大赢家／输家的波动速度作为主要优化目标，改为条件问题：长期上涨结构成立并触发日线MACD刚金叉时，什么样的回调深度、持续时间、量能收缩、相对强弱保持和动能修复能提高后续结果。
- ATR只用于标准化回调、止损和仓位，不作为方向性加分；MACD柱三日增强作为重新转强候选；QQQ/SPY与行业ETF保持独立环境层。
- 个股、大盘、行业分别生成“过度延伸／正常回调／深度回调／趋势破坏／修复”状态，再测试三层组合的增量。
- 先报告单项和少量预登记组合相对共同门票的胜率、中位收益、PF、成本后期望和回撤；不得用旧最大100共性代替对照组。
- 2025与2026结果已经用于既有实验，下一实验若因这些已见结果修改定义，必须把它们标为开发参考；独立验收使用新的滚动留出或未来未见样本。

## 评分单调性与因子归因 V1 冻结口径

- 实验 ID：`score-monotonicity-factor-attribution-v1.0.0-2026-08-29`。
- 事件门票为完整日线 MACD 刚金叉；只用事件当时冻结的技术分和因子，大盘、行业只能另表分层。
- 高分主定义为技术候选分 `>=5`；同时报告每个原始分值及冻结的 `0–2 / 3–4 / >=5` 分组。
- 原始赢家为对应固定持有窗口收益 `>0`；策略赢家为扣成本后策略盈亏 `>0`，两者不得混用。
- 高收益为每个时期和持有窗口的原始收益前 10%；同时报告绝对收益 `>=10%` 敏感度。失败对照为收益 `<=0`。
- 主分析对同一股票在最长可用窗口内只保留首个事件；全事件作为敏感度分析。
- 单因子开发期 / 2025 最低命中样本为 300 / 100；两因子组合为 200 / 75。2026 样本不足时只能标为方向观察。
- 单因子必须报告全部候选、赢家、高收益和失败样本的基础出现率，以及胜率、中位 / 去极值收益、PF 和期望增量。
- 附加因子先执行父条件；高度相关因子按家族去重。只有开发期达标且来自不同家族的因子才能进入冻结两因子组合。
- 多重比较使用 Benjamini–Hochberg 控制假发现率；不得用 2025 或 2026 重新挑因子、组合或门槛。
- 有效因子需在开发、2025 和 2026 保持同向，样本达标，且 20 / 50bps 成本后期望仍为正；否则只能归类为候选、样本不足、不稳定或不成立。
- 冻结事件池没有的逐事件窗口必须标记缺失；不得用旧聚合结果伪装成本轮逐事件结果。

## 长期证据校准每日评分 V1（pre-registered）

- 实验 ID：`evidence-calibrated-daily-score-v1.0.0-2026-08-29`。
- 对照：`unified-v2-macd-trigger-1.2.0`；挑战者：`unified-v2-macd-trigger-1.3.0`。
- 事件池不变：完整日线MACD刚金叉并满足长期趋势资格；不因改权重重建或覆盖旧事件。
- 唯一改变：B级因子只进入去重后的影子排序；C/D权重为0；上方未补缺口停止固定负分。行业与大盘仍独立保存，公式不变。
- B级影子同一冗余组只取最高项；风险方向不明确的上方缺口只观察，不给正分。
- 新模型从上线后的首个完整美股收盘开始逐日记录；旧V2冻结为历史对照。
- 每周比较候选数量、排行榜换位、精选机会、5/20/40日胜率、中位/去极值收益、PF、期望、最大回撤与换手；报告20/50bps成本。
- 挑战者只有在足够前向样本中改善收益或回撤且没有明显恶化2025独立验证一致性时，才能升级为稳定生产模型；在此之前网站必须标为证据校准挑战者，而非验证胜率。

## 完整事件池评分、周期与因子归因 V2（pre-registered）

- 实验 ID：`score-timeframe-attribution-v2.0.0-2026-08-29`；它补齐 V1 的筛选面与窗口缺口，不覆盖 V1。
- 复用 `macd-factor-history-v2.0.0` 已保存的 2000—2025 自然周候选池、年度档案和历史价格缓存；2026 复用逐日完整候选池。不得为本实验重新下载已经缓存的二十多年行情。
- 2000 只作预热；2001—2024 为开发期；2025 为一次性独立验证；2026 为前向观察。事件门票固定为完整日线 MACD 刚金叉，技术因子是主实验，大盘与行业仅可单独分层。
- 原始固定持有窗口为 `5 / 10 / 15 / 20 / 40 / 60 / 100 / 120` 个交易日；日、周、月重点窗口分别为 `5/10/20`、`15/20/40/60`、`60/100/120`。入场为下一交易日复权开盘。
- 单因子和两因子晋级主窗口冻结为20个交易日；其他窗口用于周期匹配与稳健性，不能事后挑最好结果替代主检验。
- 当前 V2 技术分、周期等权和预登记 V3（日 `1.0`、完整周 `1.5`、完整月 `2.0`）在同一事件上对照。真正的完整周线 MACD 金叉作为新增单因子单独归因，不在结果出来后偷偷加进 V3 分数。
- 高分以逐交易日技术分中位秩五分组为主，并同时报告原始分值；赢家、高收益、失败和有效因子沿用本文件 V1 冻结定义。
- 主去重按每只股票交易日索引执行：最长 120 日窗口内只保留首个事件；全部事件作为敏感度分析。收益必须同时报告中位数、1% 去极值均值、PF、期望及 20/50bps 成本。
- 单因子继续使用开发 / 2025 命中样本 `300 / 100` 门槛和 BH 假发现率控制。组合不穷举：只冻结长期复核中的跨家族 B 级组合，且必须同时优于总体基线及两个组成单因子。
- 第一阶段只做原始固定持有的评分、周期和因子归因；固定支撑止损、8%移动止损和看跌吞没 / RSI / MACD 柱衰减退出均留在独立实验，不混进因子有效性的证明。
- 每个自然周保存可恢复检查点，每年保存压缩结果；网站在全期完成前不发布临时赢家，完成后只展示总体、五年段、2025、2026与可执行层级。

## 每个实验的必交成果

- 做了什么，以及相对基线只改了什么；
- 覆盖日期、股票数、事件数、成熟样本数和数据质量；
- 胜率、平均 / 中位收益、Profit Factor、期望值、最大回撤、MFE、MAE、止损率、目标命中率；
- 开发、验证、前向三个阶段的分别表现；
- 单因子、组合及大盘 / 行业分层结果；
- 结论：`可以使用 / 候选观察 / 样本不足 / 不稳定 / 不成立`；
- 用户现在怎么用，或为何不能用；
- 限制与下一步，失败不隐藏。

## 赢家／输家驱动策略优化 V1（completed, not validated）

- 实验 ID：`winner-loser-strategy-optimization-v1.0.0-2026-08-29`；复用V2完整事件池、自然周检查点和价格缓存，不重新下载二十多年行情。
- 事件门票、下一开盘入场与120交易日主去重保持不变；主优化目标为20日原始收益，5/10/40/60/100/120日只作周期敏感度。
- 描述档保存2001—2024最高100与最低100事件；真正的候选发现只使用2001—2018，2019—2024作为开发期内部校准，2025独立验证，2026前向观察。
- 同时检查已登记因子和冻结的连续技术特征。连续特征只从开发发现期的20%/80%分位形成低／高阈值候选，不进行任意阈值穷举。
- 候选需在最大100、全部前后10%、开发期两个子段和年度方向中共同成立；同一家族只保留一个。权重只用 `-2/-1/+1/+2`，不得用2025/2026调参。
- 挑战者相对共同门票和当前1.3.0影子排序报告五分组、秩相关、胜率、PF、中位、1%去极值、20/50bps后期望、样本与换手。2025是主验收，2026不得方向性崩溃。
- 技术权重单独优化。大盘另表；历史股票—行业成员关系若无带日期快照则记为不可用，行业沿用ETF独立研究及2026之后前向关联，不能混入技术挑战者。
- 最高／最低100逐事件明细只保存在GitHub压缩产物；仓库与网站保存紧凑共性、冻结权重、三时期对照、限制和可执行结论。
- 完成覆盖62,040个特征事件、13,270个120交易日去重样本；发现 / 校准 / 2025 / 2026分别786 / 9,227 / 1,895 / 1,166。
- 冻结挑战者在2025最高组的50bps后期望/PF相对共同门票低0.7065个百分点/0.1665；2026低0.7115个百分点/0.1332，结论为 `not_validated`。
- 最大100必须另存年份分布和异常标记：本次最低100中2020占59个；MEL等接近归零事件在公司行动／代码变更审计完成前不得主导任何阈值或权重。
- 可执行决定只有两项：生产1.3.0不变；下一版若继续优化，预登记时必须把可靠性目标和尾部收益目标拆开。2025/2026结果已经看过，不能再冒充下一版的全新独立验证集。

## 永久留档

- 成功、失败、负结果、样本不足和中断都只追加、不删除、不覆盖。
- 机器账本：`research/experiments.jsonl`。
- 网页目录：`public/experiment-catalog.json`。
- 大文件、分块结果和日志：版本化输出或 Actions artifact。
- 每条实验保存规则版本、配置、代码提交、数据范围、断点、摘要和产物路径。
- 旧实验数据继续可读；新口径通过迁移实验追加，不重写历史。

## 实验时间线与中文总结

- 每个实验必须有生命周期事件：`registered / started / checkpoint / completed / blocked`，事件只追加、不覆盖。
- 新实验至少记录登记时间、实际开始时间和完成时间；长任务的每个周断点也记录发生时间与完成范围。
- 旧实验没有单独保存结束日志时，以该实验首次提交 GitHub 的提交时间作为“历史完成记录时间”，同时保存 `time_source=git_commit`，不得冒充精确运行结束时刻。
- 原始实验定义与机器结果继续保存在 `research/experiments.jsonl`；生命周期保存在 `research/experiment-events.jsonl`。
- 每条实验必须有中文名称、研究问题、人话结果、现在怎么用、结论状态和下一步，维护在 `research/experiment-summaries.zh.json`。
- 生成的 GitHub 总结 `docs/EXPERIMENT_SUMMARY_ZH.md` 与网页目录必须来自同一数据源，避免网站和仓库各说一套。
- 通用研究、数据基础设施、失败、负结果和样本不足同样进入总结；“没有产生可交易优势”本身也是有效收获。

以后新增实验不需要重做 UI：只追加一条原始实验定义、一条或多条生命周期事件和一份中文摘要，再运行 `python3 -m services.scanner.experiment_catalog`。生成器会校验是否漏记时间或中文结论，并同时更新网页目录与 GitHub 总结；长任务继续追加 `checkpoint` 后即可从最后断点续跑。

## 结论如何进入规则

- 稳定有效且获准使用：登记到 `11_VALIDATED_PLAYBOOK.md`，再考虑升级正式评分。
- 明确危险、重复造成损失且证据充分：登记到 `12_HARD_RULES.md`。
- 样本不足或不稳定：留在实验目录，不进入宝典或红线。
