# 10｜网站、自动化与生产交付规则

版本：`1.12.0`
最后更新：2026-08-30

## 本文件负责

网站每页要解决的问题、实用表达、版本、每日更新、部署、线上核验和通知。

## 网站宗旨

网站是项目最终可用成品，不是工程日志。每个主要页面必须直接回答：**这是什么、数据更新到哪天、分数怎么来、我现在怎么用、有什么限制。**

## 页面职责

| 页面 | 首要问题 | 必须显示 |
|---|---|---|
| 今日总览 | 今天先看什么 | 大盘置顶、当天精选、关键原因、风险、数据日期 |
| 多因子机会 | 排名为何如此、个股为什么值得看 | 唯一排行榜、技术 / 行业 / 大盘分项、精选子集、个股日周月详情、主导周期、冲突与风险计划 |
| 我最喜欢形态 | 今天哪些股票正接近个人最佳形态 | 两段确认时间线、当前候选、图形与关键位、7阶段证据、ADBE正例、TTD/AEVA反例、前向样本 |
| 行业与大盘 | 市场和热点如何 | 趋势、广度、风险偏好、ETF 热点、个股关联 |
| 历史与实验 | 哪些方法有用 | 实验做什么、胜率与关键指标、能否使用、怎样使用 |
| 策略宝典 / 红线 | 已经学到了什么 | 有效组合、适用条件、严格禁区及证据 |

## 实用性规则

- 结论在前，工程细节折叠；失败和限制不能隐藏。
- 过期候选必须标日期与状态，不得冒充今日推荐。
- 每一分可追溯；不能只写“高分”而没有命中与未命中项。
- UI 版本固定显示在顶部；数据、模型、因子与策略版本可核对。
- 桌面和移动端工具栏对齐，正文可读，功能区分明显。
- 历史与实验首页先显示正在进行、已完成、可以使用、不可使用四类数量；每条实验直接显示中文名、版本、登记 / 完成时间、做了什么、得到什么、现在怎么用。
- 工程 ID、英文原始结果、完整限制和配置放入单条实验的折叠审计，不再把原始 JSON 式文本当作主要 UI。
- 行业与大盘必须在同一主要页面先显示今日大盘结论、趋势 / 广度 / 风险偏好，再显示领先行业、回调观察、修复行业和数据不足；表格是证据，不是首页答案。
- 多因子机会页的因子库必须在排行榜前用四象限回答：`正在使用 / 候选观察 / 暂停加权 / 准备弃用`。象限表示当前处理动作，卡片还必须单独显示生产角色和最新研究结论；“正在使用”不得冒充“已验证有效”。
- 同一因子家族在四个象限中使用同一稳定颜色，并同时显示家族文字，不能只靠颜色传达含义。象限状态使用独立标题、边框和动作文字，不能与家族色混淆。
- 四象限和“现在能直接用的结论”必须读取最近完成且已审计的实验摘要；不得继续以短期机会账本或旧实验摘要覆盖更新的全期研究。
- 因子被标为“准备弃用”时仍保留机器定义、历史命中和失败实验；这里表示从主研究视图与未来评分候选中退休，未经迁移批准不得删除历史证据。
- 多因子机会页只保留当前决策链：今日摘要、最新审计结论、四象限因子库、唯一排行榜、选中股票的周期与风险解释、永久机会账本。旧系统历史排行、旧因子库、独立股票触发查询、旧评分兼容观察和旧规则说明不得继续在该页展示或加载。
- 从多因子机会页移除旧模块只表示退出产品主界面，不删除历史JSON、实验产物或失败记录；需要复核历史时统一进入“历史与实验”页或GitHub留档。
- 后续图表版必须等待相应回测数据口径冻结；收益曲线、分组条形图和样本构成图不得把观察分包装成收益概率。
- 因子家族组合实验完成后，多因子机会页增加一张精简“组合收益对照”卡，只显示最高收益组合、共同门票、滚动留出、已见2025/2026、样本和可用状态。完整15组合、年度明细与匹配对照只保存在GitHub和实验档案，不重新堆回主页面。
- “我最喜欢形态”必须是一个独立、单一目的页面，不恢复旧MACD Tracker的全部排名、查询、旧评分或重复因子库。首屏用阶段漏斗和候选数量回答“现在走到哪一步”，候选详情用价格／EMA曲线、两底、三推趋势线、突破位与前高目标解释机器判断。
- 页面固定显示“匹配度不是胜率”；达到最低前向样本门槛前，只展示样本积累和可人工复查案例，不展示暗示有效性的胜率结论。
- V2页面以时间线显示第一段确认、真实重置、第二段突破／MACD／EMA转强和完整均线排列日期；不得再次压缩成一个看似同日发生的总分。风险闸门必须与正面进度并列，不得藏在折叠区。
- 组合卡必须明确区分`历史收益冠军`、`通过滚动门槛的零权重候选`和`生产正在使用`；历史冠军不得以绿色通过态或“最佳买入策略”表达。实验处于预登记或运行中时，网站只显示进行中，不提前展示临时赢家。

## 自动更新和发布

权威顺序：生成数据 → 数据审计 → 测试 → 保存版本 → 构建 → Cloudflare 部署 → 线上核验 → Discord。

- `main` 上的 UI、实验定义或实验目录发生变化时，网站发布工作流自动构建、测试和上线；不依赖等到下一个交易日。
- 每日 EOD 工作流使用 `main` 上当前已批准的生产规则，原子生成大盘、行业、个股、排行榜和永久跟踪数据，然后测试、发布并核对线上日期。
- 时间敏感的每日 EOD 不得只依赖 GitHub `schedule`。Cloudflare Cron 是独立主触发源，使用限定到本仓库 Actions 写权限的专用令牌 dispatch 同一条日终工作流；GitHub schedule 只作备用。两者都必须复用同一幂等入口，不能另算一套行情。
- 独立新鲜度检查同样由 Cloudflare Cron 触发。若数据源已有更新而网站仍落后，检查任务必须自动 dispatch 一次 `freshness_recovery` 日终更新；恢复任务仍走完整的数据审计、测试、部署、线上核验和通知闸门，不能绕过任何一步。
- 日终运行必须记录 `cloudflare_cron / github_schedule / freshness_recovery / manual` 触发来源。重复触发在确认全套数据与当前因子版本一致后以 `already_current` 安静退出。
- Cloudflare 调度器不得复用个人广权限登录令牌。专用令牌只允许访问本仓库并具有触发 Actions 所需的最小权限；只能作为 Cloudflare secret 保存，禁止进入 Git、普通变量、日志或公开产物。
- Cloudflare 只配置两条 Cron Trigger：一条覆盖日终候选窗口，并由 Worker 内部 UTC 白名单保留原有7个精确启动时点；另一条独立触发新鲜度检查。非白名单唤醒必须立即空退出，不调用 GitHub，避免超过免费账户5条 Cron Trigger 的额度，也不能借合并改变实际生产时间。
- 没有新完整交易日时保留上一交易日的有效数据，不伪造“今天”数据；代码和 UI 更新仍走独立自动发布通道。
- 实验规则可以持续新增，但在回测通过并更新规则手册前，不得因一次代码合并自动替换生产评分。
- 任何关键数据错位、测试、构建或线上核验失败都停止通知。
- Discord 读取已发布的同源结果，不另算一套分；同股票、日期、状态去重。
- 每日生产与多年回测隔离，回测失败不能拖死当天更新。
- 历史与实验页必须显示夜间回测是否启用、已保存覆盖范围、下一周断点、当前生效规则版本和最近成功批次；不能只在 Actions 日志里显示。
- 夜间回测每次只处理一个自然周并先保存周产物；失败不移动断点，下一晚重试同一周。新增规则只影响后续新批次，旧批次保留原版本。
- 多周批量回放仍必须把每个自然周作为独立可恢复产物；只有全部周成功后才汇总、提交和发布。
- 完整研究周产物与网站视图分开：网站保留最近30个交易日的完整因子审计；更早日期保留排名、分数、原因及已命中因子，省略大量重复的“未命中”明细，以符合网站单文25MiB限制。
- 2000—2025 长期回放不逐年合并进网站数据：每个自然周明细和年度压缩包保存在 GitHub Actions；整个时期完成后，网站只发布总样本、五年分段、2025独立验证、2026前向观察、因子层级和退出对照，不发布逐笔明细。
- Secrets 只用于运行环境，报错不得打印带 Token 的完整网址。
- 向用户交付时提供生产链接；未部署要明确说“代码完成但生产未更新”。

## 当前优先级

先保证技术扫描、评分、追踪、实验结论真实可用，再精进行业、大盘和整体视觉。不能为了美化掩盖数据或策略尚未完成。

旧“个股研究 / MACD Tracker”页面和旧排名仍保持退役。新“我最喜欢形态”是用户批准的单一形态状态机，不恢复旧排名、旧评分、旧查询或重复因子库；通用个股因子审计仍由“多因子机会”承接。

## 联动条件

页面只改变表达时只改本文件；如果改变分数、选择或实验结论，必须回到对应业务模块先改规则。
