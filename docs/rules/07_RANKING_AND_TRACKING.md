# 07｜排行榜、精选机会与永久追踪规则

版本：`2.1.0`

## CR056获批候选榜边界

CR056新提名与持续复评共用唯一分数；稳定watch不含政策版本，初次金叉后复评不重新要求金叉。原提名冻结，失格退出当前排名并保留历史，恢复资格不冒充新提名。services/ledger/cr056.py维护观察身份及5会话警报冷却，services/scanner/cr056_public.py只投影结果。候选comparison不升格formal。 用户已授权真实重排及现有页面更新；已发布9月4日快照并沿既有日终流程接通自动复评；页面必须如实显示独立日期、落后和失败提示，接通不等于已取得跨交易日运行证据。原批准/预登记见提交acfc061，交付证据集中见[CR056](../CHANGE_REQUESTS_ZH.md)。后续核对首个跨交易日续跑，再大盘行业、回测。

## 本文件负责

统一排行榜、精选 / 稀有机会、历史事件账本和触发后的前向追踪。

## 每日榜单与总榜：本轮确认，尚未实施

- 用户确认每日榜单与总榜两张榜；每日榜是同一评分结果的子集，不设第二套排序或计算。日线MACD在当日完整收盘金叉是新提名门票，随后通过月周方向及其他许可、计分条件。
- 新提名的新鲜度先暂定半年，替代讨论时举例的一年，不是已经回测验证的最佳参数。首次出现，或此前半年未出现在合格总榜且当日重新满足门票和筛选，进入每日榜并加入总榜；不能因历史上曾提名就永远排除“新”。
- 判断依据是最近一次实际上合格总榜的日期，不是扫描日期、后台仍有watch、首次提名日期或当日名次。连续在榜不因半年届满自动变新。用户接受此业务口径；实现暂按6个日历月理解，精确边界与历史不足处理见下方待定项。
- 永久保留首次提名、历次提名和原版本，展示本次提名及最近上榜日期；再次提名追加事件，不覆盖原提名，不重置股票身份。展示可区分首次/再次提名。
- 总榜每日复评分，无需再次金叉；失格退出当前合格排行，观察历史保留。仅资格恢复且未满足半年新鲜度及当日金叉，不能标为每日新提名。是否买入由09规则负责，总榜持续高分不重复触发本轮回测买入。
- 每日检测没有合格新提名是有效结果；展示实际数据日、检测状态、门票触发数、筛选通过数和符合新鲜度数量，来源不足单列。不得用“0新提名”掩盖没运行或历史不可用，也不为了有新股票放松条件。
- 当前代码仍沿用旧watch新提名语义，未实现半年规则和完整再提名展示。本节是下一版目标，下方旧版“恢复不冒充新提名”按其原政策保留，不能据此否定本次已确认方向。

### 实施前剩余边界（不冒充用户决定）

- “半年”暂拟按6个日历月、检查当日前的上榜记录；窗口端点应在实现前固定。旧数据不足半年时不能把“查不到”当“从未上榜”，需选定历史证据不足的处理。
- 旧研究的120交易日去重是实验统计口径，不等于本节新提名资格；未来新实验显式冻结口径，不改旧研究。

## M07唯一排行与历史保护（已批准影子实施）

- 新formal主榜只能由`services/ranking/`创建`RankingSnapshot 2.x`；同一输入身份和一组政策只能对应一份权威快照。
- `ranking_policy_version`保存完整排序键、方向、稳定并列键和候选截断；最终并列使用稳定`instrument_id`，不得依赖输入顺序或ticker。
- `authority_policy_version`与评分、排序分开。某日期至多一个获批权威组合；“最新版本”不能自动成为历史权威。
- V2只从明确批准的生效日开始成为权威。对更早日期运行V2只能生成`comparison`并引用原快照，不能覆盖或伪装成当时榜单。
- 每个快照逐股守恒：每个complex assessment恰好进入排行或一个明确排除原因；缺失、重复或未知原因失败关闭。
- 精选仍是主榜严格有序子集。个人形态继续独立观察，不使用主榜`rank`，不得建立第二张权威主榜。
- M07止于评分和排行，不判断交易就绪，不生成交易计划、后续收益、总账、人工审核或Excel。
- 当前旧排行和公开JSON保持原样；M07只在系统临时目录或仓库`work/`进行内容寻址、只追加影子存储，生产切换留给M12。

## 唯一排行

- 当前尚未迁移的旧生产排行先按技术共振分、跨周期奖金、家族数和原始正向颗数排序，技术键完全相同时仍保留旧行业／大盘同分行为。M07影子排行不使用上下文改变排序，最终并列直接使用稳定`instrument_id`；未来若要改变必须建立新排序政策并另行批准。
- 精选 / 稀有机会必须是该排行榜的严格有序子集；第一名不同必须给出可审计理由。
- 当天没有股票达到门槛时，明确显示“今天没有精选机会”，不能用昨天候选冒充今天推荐。
- 排行只使用当日及以前的数据；未来收益只负责评价，不能参与历史排序。

## 可审计详情

每只股票必须显示当时价格、触发日期、模型版本、技术分、行业调整、大盘调整、总公式、每个因子的命中 / 未命中 / 不可用 / 风险扣分，以及支撑与退出计划。

排行榜和个股详情还必须显示周期画像：`日线主导 / 周线主导 / 月线主导 / 多周期共振 / 短期战术观察`。标签旁展示日、周、月各自贡献和证据数，并明确“实验描述，不代表已验证持仓期”。

## 永久事件账本

### M09唯一事件总账（已批准影子实施）

- 新formal事件只能由`services/ledger/`创建`OpportunityEvent 2.x`；事件根固定为`instrument_id + signal_date`，同一上市实体同一天不得因模型、排行版本或计划状态重复建根事件。
- 只有M07 `ranking_role=authoritative`且`path_status=formal`的`ranked_entries`创建正式事件。`shadow`与`comparison`留在M07不可变快照，不进入formal事件生产器；排除项不伪造事件。
- 所有入榜条目均建立事件，`selected`只决定M08是否尝试建计划。未精选、计划缺失或`unavailable`不能删除事件。
- 事件只冻结M03—M08稳定ID、版本、内容指纹和经M07验证的当时排行事实，不重新计算Gate、因子、模型、上下文、评分、排序、计划或退出。
- 入榜日立即创建事件。M08计划决定、计划和退出状态通过独立机器记录追加，不修改事件。
- 机器记录与人工记录分开。人工审核必须包含稳定非空`author_id`、时间、正文和类型`observation`／`hypothesis`／`approved_change`；修改批注只能新增带`supersedes_review_id`的记录。
- `approved_change`只表示用户批准了变更意图，必须带治理／M11批准引用；它不表示实现、验证、部署或生产启用，也不能改写旧事件。
- 相同身份相同内容允许幂等重放；相同身份不同内容失败关闭。事件、机器追加和人工审核均只追加，不接受“最新覆盖旧值”。
- 旧Opportunity Ledger、Signal History及其轻量视图只读对账。缺少稳定身份或只有ticker＋日期时标记`ambiguous`，不得猜测升级为formal。
- 当前仅允许系统临时目录或仓库`work/`影子存储；生产目录、Manifest、网站、Discord和工作流切换属于M12。

### 旧生产账本（M09迁移前保持原样）

- 真实发布、历史恢复和回测事件进入同一结构，但明确标注来源。
- 首次触发时冻结日期、价格、版本、排名、分数公式、因子状态、大盘、行业和风险计划。
- 掉榜只改变 `current / expired / historical / matured` 状态，不删除记录。
- 同一股票以后重新触发时建立新事件，不覆盖旧事件。
- PG、MARA 等历史记录保留当时的旧分与版本；可以追加“按新模型观察”，不能改写历史。

## 旧生产账本当前持续前向跟踪（M10责任，不属于M09）

从触发日起按交易日追加价格、状态变化、1/5/20/40/60/100 日收益、MFE、MAE 和策略退出结果。原始信号表现与带止损止盈的策略表现分开统计。

## 个人形态 Tracker 的边界

- “我最喜欢形态”与唯一复杂排行并列但不竞争排名；V3先按`4/4形态完整且风险清除 → 4/4风险阻断 → 3/4等待 → 更早期`排序，再按突破新鲜度和流动性排序。页面必须写明“颗数不是收益概率”。
- 首次风险清除的4/4简化形态才写入V3前向事件；同一结构连续命中和V1/V2旧事件不得重复开仓或重复记样本。
- `形成中 / 双底确认 / 等待突破`只表示观察进程，不属于买入信号，不进入永久机会账本。
- 只有完整日K收盘达到`entry_ready`才建立`favorite_pattern_tracker`来源的前向案例；冻结当时的回调、两底、三推高点、突破位、Golden Pocket／EMA承接、风险闸门和形态版本，最早下一交易日复权开盘入场。
- BABA作为形态语言教学案例、ADBE作为时序教学案例继续显示；TTD／AEVA作为风险回归案例单独显示。PG只保留在V1历史账本，不再出现在V2参考卡。
- 正式`entry_ready`、`near_match`和`blocked_near_match`必须分区。近似样本保存已完成机制、缺失条件、风险阻断和首次观察日，但不建立前向交易案例、不进入生产排行或通知。
- 每次回测与人工审计的漏检赢家、误收输家和边界样本要保存选择口径、机器原判断、人工判断与`post_hoc_hypothesis`，后续版本不得覆盖原记录。
