# 12｜交易红线与硬规则

版本：`1.2.0`
最后更新：2026-09-05

## 本文件负责

收录从回测、前向跟踪或真实交易亏损中确认的严格禁区。红线优先于机会分数；命中红线时，不因其他因子高分而忽略。

本文件明确区分系统完整性硬规则和需要收益／风险证据的交易alpha红线。M11设计见`../M11_STRATEGY_PROMOTION_GATE_DESIGN_ZH.md`；本次只冻结晋级边界，不新增交易红线。

## 两类硬规则

### 系统完整性硬规则

防未来、不可覆盖、数据缺失失败关闭和已批准执行纪律保证系统诚实性，不是交易alpha，不要求用收益样本证明。修改仍需治理批准、实现证据；影响生产时仍需M12激活证明。

### 交易alpha／风险红线

形态、因子、市场环境、入场或退出条件要成为active红线，必须通过M11完整证据闸门：精确候选／基线版本、预登记、独立验证、可执行条件、适用范围／例外、解除条件、用户批准、进入main证明和M12激活证明。单个赢家、亏损或人工直觉只能形成候选。

## 收录门槛

- 必须有可追溯证据：实验、前向事件或真实交易记录。
- 写清造成损失的机制、适用范围、机器可执行条件和例外。
- 区分“永久风险原则”与“可被新证据解除的临时禁区”。
- 新想法或单个案例先进入观察，不直接升级红线。
- 红线新增、放宽或解除都需要用户批准，并保留历史版本。
- 发现／校准案例不得同时充当独立验证；必要证据缺失时保持观察或`evidence_incomplete`。
- `validated`、用户批准、进入main和生产active必须分别有证据，不能互相替代。

## 当前系统级硬规则

以下是研究与执行完整性的硬规则，不是未经验证的交易 alpha：

1. 不使用未来数据、未完成周线或未完成月线做历史决策。
2. 不用今天的规则重写历史事件当时的分数、排名与证据。
3. 不把未验证实验分、规则匹配分写成胜率或收益承诺。
4. 关键数据日期错位、缺失或质量闸门失败时，不发布新推荐。
5. 命中已冻结结构止损或最大风险边界时，不因高分取消风险纪律。
6. 没有客观支撑时，依赖支撑的底部形态不得独立加分。
7. 已经验证、批准并启用的退出条件触发后，不因原始高分、周线 / 月线标签或主观期待继续拖延退出。

## 待交易证据验证的禁区

当前暂无经过统一回测与批准的形态类永久禁区。后续实验和真实亏损教训必须按模板追加，不能只留在聊天中。
