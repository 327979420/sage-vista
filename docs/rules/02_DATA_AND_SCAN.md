# 02｜数据与每日扫描规则

版本：`1.7.0`
最后更新：2026-09-01

## 本文件负责

权威交易日、扫描股票池、MACD 触发、深度检测顺序、防前视与发布前数据校验。

## 当前扫描流程

完整美股收盘数据 → 数据审计 → 日线 MACD 当日金叉事件 → 按月线、周线、日线检查其余因子 → 保存当日快照与历史事件。

- 日线 MACD 是降低计算量、统一事件起点和寻找择时的“门票”。
- 它不是“只测试 MACD”，也不单独构成买入结论。
- 即使大盘不适合交易，技术扫描仍运行并保存事实。

## “我最喜欢形态”独立日更扫描

- 主多因子扫描继续以“完整日线 MACD 当日刚金叉”为事件门票；本页不得改变这条门票或生产候选分。
- “我最喜欢形态”是独立的简化形态扫描，不是第二套生产排行榜。V3每天复用同一批完整复权日K和活跃股票池，只回答四件事：是否有客观回调、是否形成宽口径双底、是否完成三推下降趋势线的完整收盘突破、两底是否至少一次落在Golden Pocket或EMA20/50/200容差带。
- V3不要求七阶段、第二次重置、MACD再次金叉或EMA20正式上穿EMA50；这些旧V2字段继续只读保存作解释与新旧对照，不再决定V3形态是否完整。
- 简化形态可以在非MACD金叉日进入观察，因为它服务人工形态复核；这个例外不得回写主多因子门票、排行或技术共振分。
- 本扫描不强制股票在形态开始前已经满足长期上涨资格；BABA与ADBE只教位置、结构和突破语言，不能为迎合案例修改阈值。
- 形成中和等待突破只进入当日观察表；只有完整日 K 收盘后达到`entry_ready`，才按下一交易日复权开盘口径进入永久前向账本。历史图片和人工画线只用于解释，不得作为机器事实输入。

## 数据纪律

- 所有生产 JSON 使用同一个已经完整收盘的美国交易日。
- 历史计算只能读取 `as_of` 当日及以前的数据。
- 周线和月线只能使用已经完整收盘的 K 线。
- 确认型 pivot 必须等待规定的右侧确认。
- 复权、股票池、退市股票、流动性门槛与数据源都要版本化。
- 数据缺失、日期错位、未来数据或关键覆盖率不足时停止发布。

## 缓存与复用

- MACD 触发事件池按日期保存，可供新增“触发后附加因子”重复研究。
- 仅新增触发后因子时，不应重扫所有股票全部历史。
- 触发器、股票池、价格调整、数据源或权威交易日定义改变时，才重建受影响的事件池。

## M02行情仓与股票池影子规范

- 唯一中立行情层位于`services/market_data/`，并复用`services/contracts/`的`MarketDataSnapshot`和`UniverseSnapshot`。扫描器、回测和研究不得复制合同定义或各自建立新的下载／复权入口。
- 所有用于选择、门票、因子和上下文的历史行情读取必须显式提供规范`as_of`；返回的最晚日期不得晚于`as_of`。缺少截止日、日期非法或发现未来行时失败关闭。
- 原始行情只保存一份完整历史。消费者只能读取点时视图，不得直接追加、裁短或覆盖仓库文件；窗口裁剪在只读视图中完成。
- 供应商改写旧行时，追加修订记录必须包含变化日期、旧行、新行、变更前后完整内容指纹和修订链身份。证据不足以重建旧版本时明确标记`not_reconstructible`及原因，不得猜测。
- 股票池成员来源、稳定证券身份、生效日、层级和资格规则必须版本化。成员可在生效后继续存在，但资格是逐日事实：新正式历史路径只接受与查询日相同`as_of`的资格快照；缺少同日证据时返回`universe_unavailable`，禁止延用旧资格或用当前活跃名单回填。
- 现有每日和夜间消费者在迁移完成前保持原样，统一标为`legacy`路径；M02影子建设不得中断、替换或改变其结果。正式失败关闭只在未来新路径完成迁移并另获批准后生效。
- 本地未恢复云端完整缓存时，只能用固定小样本验证纯逻辑。线上2026-08-28的1337只合格股票与31只MACD触发是未来行为等价基线，不代表A—C已经本地复现。
- `UniverseSnapshot`从M02影子结构`2.0.0`起把成员事实和当日资格事实分开保存。成员必须有完整稳定证券ID、当时ticker、层级、listing状态、成员来源和生效日；资格必须逐证券保存价格完整性、最低价格、成交额、历史长度、是否合格及明确纳入／排除原因。
- `formal + complete`和`legacy + legacy_observed`是两条不可互换的路径。正式快照必须为每名成员保存同日资格证据；legacy只描述机器实际观察到的成员，禁止声称完整。两条路径在查询日没有已知快照时都返回`universe_unavailable`，不得回退到今天名单。
- `universe_id`必须由成员、成员来源、资格事实、资格规则、路径、覆盖状态和来源版本共同计算；显示顺序和生成时间不改变ID，任一事实变化都建立新身份，旧快照不覆盖。
- 同一`as_of`、`effective_from`和路径出现不同`universe_id`属于“快照冲突”，必须失败且不得按输入或文件顺序择一；完全相同的重复ID可以安全去重。
- 股票池快照和M02行情仓都只能写入测试临时目录或调用者明确`workspace_root`下被Git忽略的`work/`影子目录，并共用同一个根目录守门与原子写入口。生产`public/`、`automation/`、仓库根目录、旧缓存和历史结果不得成为写入目标；非法根目录必须在数据源调用及文件创建前失败。`workspace_root`是可信内部能力，未来只能由唯一消费者入口从仓库内部固定取得，禁止直接来自CLI参数、环境变量、下载内容或用户输入；F实施时必须增加消费者集成测试证明这一边界。
- 仓库只有2026-08-28筛选后合格数量1337及31只MACD触发明细，没有筛选前权威完整成员来源和全体同日纳入／排除证据。1337不是筛选前成员总数，即使有全部合格名称也不能证明完整覆盖；31只触发更不能代表股票池。因此该日正式快照当前为`universe_unavailable`，不得从今天名单、计数、缓存文件名或触发股票倒填。
- 正式股票池只从未来第一个完整成功保存的交易日向前追加，不回填2026-08-28或更早日期。每个正式日必须同时保存权威完整来源成员和每名成员同日的纳入或排除证据；来源不完整、身份冲突或缺少任何资格结论时，整日失败关闭。
- 前向正式证券身份以`provider + market + exchange + provider_code + observed_listing_epoch`建立。`observed_listing_epoch`只表示系统第一次完整观察到该上市实体的日期，不得冒充IPO日期；ISIN只是辅助证据。证券消失后重现、交易所变化、供应商明确重上市或身份冲突时，必须建立新epoch和新证券ID，不得覆盖旧身份。快照必须保存可人工解释的身份依据，不能只留下哈希。
- 上述前向身份和完整来源证据属于新的破坏性合同语义，因此使用`UniverseSnapshot 3.x`；既有`2.x`继续只读验证，不得静默改变含义。正式与`legacy_observed`必须由调用者显式选择，正式缺失时禁止自动回退legacy；legacy返回值必须带幸存者偏差和成员证据不完整说明。
- 唯一影子消费者入口从仓库代码位置固定取得`workspace_root`，不接受CLI、环境变量、下载内容、当前工作目录或外部调用者注入根目录。M02只影子接入每日和回测读取，现有生产入口与输出保持不变。

## 输出契约

每个事件至少保存：股票、触发日期、信号收盘价、数据版本、扫描版本、完整因子状态、缺失原因和生成时间。

## M01共享合同规范

- 生成器、回测、发布准备和核验未来共同使用中立的`services/contracts/`；它不属于扫描器私有逻辑。扫描器和回测不得复制合同定义，网站不得自行维护旧JSON转换逻辑。
- 十类合同、字段级必填项、稳定ID、兼容规则和结构示例的唯一正式设计见`../M01_SHARED_CONTRACTS_DESIGN_ZH.md`。本规则只冻结长期边界，避免两处重复维护字段表。
- 落盘合同根对象的`schema_version`只表示合同结构SemVer；旧格式经过适配时另记`adapter_version`；业务模型、数据政策或生成逻辑版本另记`source_version`。三者不得互相冒充。
- 新格式只接受已知主版本；同主版本只允许新增向后兼容的可选字段。未知主版本、缺少安全必填事实或`future_data_used`不是明确布尔`false`时，验证失败关闭。
- 每个旧生产JSON只能有一个明确的只读适配入口。适配器不得回写旧文件、改写历史、复制大型历史数据或猜测缺失事实；不能确认的可选事实写`unknown`，不能确认的安全必填事实直接失败。
- ReleaseManifest覆盖完整生产发布包，并用`web`、`discord`、`audit`标注用途。用途不等于加载要求：网页仍只加载自身需要的轻量文件，不得因Manifest把完整历史或审计文件放进首屏。
- Manifest按时间语义分别校验：`daily_snapshot`必须与发布日一致且防未来明确为`false`；`versioned_config`不要求日期和防未来字段，只检查版本引用；`research_summary`只要求研究覆盖末日不晚于发布日并保存来源实验。
- `factor-registry.json`是`versioned_config`，其`registry_version`必须与当日因子快照和模型引用一致；不得为它伪造`as_of`或`future_data_used`。
- `decision-summary.json`是`research_summary`，不得作为扫描、评分或排行输入；Manifest仍校验其大小和SHA-256，并要求`coverage.end`不晚于发布日及`source_experiment`存在。
- M01只在测试临时目录或被Git忽略的`work/`影子生成Manifest，并使用2026-08-28现有样本验证；不得写入`public/`，不得改变当前生产JSON、网站、Discord、工作流或线上核验。
- 每日生产候选目录、真实生产Manifest、网站与Discord按同一`release_id`读取、线上逐项核验、受控切换、部署和回退演练全部属于M12，必须另行设计和批准。
- 旧文件适配和Manifest不能只核对外层日期标签与文件哈希：适配器声明的时间、版本、合同范围和防未来证据必须能从同一次读取的真实文件字节重新得到；未知证据保持未知或失败，禁止硬编码安全结论。
- Manifest文件条目的结构主版本必须同时受其全部`contract_types`支持；类型组合没有共同主版本时失败，不能猜测。`UniverseSnapshot 2.x`只可作为支持2.x的条目，仍为1.x的合同拒绝2.x。旧`daily-factor-snapshot.json`没有完整成员和逐只资格，不得被适配器标成`UniverseSnapshot`。`required`等布尔字段必须是布尔值；同一组文件不因排列顺序产生不同`release_id`。影子写入器也必须先完成合同验证，不能把任意字典写成装箱单。
- 点时行情读取分为两道检查：仓库写入前验证完整缓存；历史选择时只让`as_of`及以前的OHLCV内容参与结果。截止日之后的合法或损坏OHLCV不能改变过去视图，但日期本身缺失、重复或乱序仍属于整份缓存无法安全分割的结构错误。
