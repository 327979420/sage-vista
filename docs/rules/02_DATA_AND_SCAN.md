# 02｜数据与每日扫描规则

版本：`1.4.0`
最后更新：2026-08-31

## 本文件负责

权威交易日、扫描股票池、MACD 触发、深度检测顺序、防前视与发布前数据校验。

## 当前扫描流程

完整美股收盘数据 → 数据审计 → 日线 MACD 当日金叉事件 → 按月线、周线、日线检查其余因子 → 保存当日快照与历史事件。

- 日线 MACD 是降低计算量、统一事件起点和寻找择时的“门票”。
- 它不是“只测试 MACD”，也不单独构成买入结论。
- 即使大盘不适合交易，技术扫描仍运行并保存事实。

## “我最喜欢形态”独立日更扫描

- 主多因子扫描继续以“完整日线 MACD 当日刚金叉”为事件门票；本页不得改变这条门票或生产候选分。
- “我最喜欢形态”是独立的简化形态扫描，不是第二套生产排行榜。V3每天复用同一批完整复权日K和活跃股票池，只回答四件事：是否有客观回调、是否形成宽口径双底、是否完成三推下降趋势线的完整收盘突破、两底是否至少一次落在Golden Pocket或EMA20/50/200容差带。
- V3不要求七阶段、第二次重置、MACD再次金叉或EMA20正式上穿EMA50；这些旧V2字段继续只读保存作解释与新旧对照，不再决定V3形态是否完整。
- 简化形态可以在非MACD金叉日进入观察，因为它服务人工形态复核；这个例外不得回写主多因子门票、排行或技术共振分。
- 本扫描不强制股票在形态开始前已经满足长期上涨资格；BABA与ADBE只教位置、结构和突破语言，不能为迎合案例修改阈值。
- 形成中和等待突破只进入当日观察表；只有完整日 K 收盘后达到`entry_ready`，才按下一交易日复权开盘口径进入永久前向账本。历史图片和人工画线只用于解释，不得作为机器事实输入。

## 数据纪律

- 所有生产 JSON 使用同一个已经完整收盘的美国交易日。
- 历史计算只能读取 `as_of` 当日及以前的数据。
- 周线和月线只能使用已经完整收盘的 K 线。
- 确认型 pivot 必须等待规定的右侧确认。
- 复权、股票池、退市股票、流动性门槛与数据源都要版本化。
- 数据缺失、日期错位、未来数据或关键覆盖率不足时停止发布。

## 缓存与复用

- MACD 触发事件池按日期保存，可供新增“触发后附加因子”重复研究。
- 仅新增触发后因子时，不应重扫所有股票全部历史。
- 触发器、股票池、价格调整、数据源或权威交易日定义改变时，才重建受影响的事件池。

## 输出契约

每个事件至少保存：股票、触发日期、信号收盘价、数据版本、扫描版本、完整因子状态、缺失原因和生成时间。

## M01共享合同规范

- 生成器、回测、发布准备和核验未来共同使用中立的`services/contracts/`；它不属于扫描器私有逻辑。扫描器和回测不得复制合同定义，网站不得自行维护旧JSON转换逻辑。
- 十类合同、字段级必填项、稳定ID、兼容规则和结构示例的唯一正式设计见`../M01_SHARED_CONTRACTS_DESIGN_ZH.md`。本规则只冻结长期边界，避免两处重复维护字段表。
- 落盘合同根对象的`schema_version`只表示合同结构SemVer；旧格式经过适配时另记`adapter_version`；业务模型、数据政策或生成逻辑版本另记`source_version`。三者不得互相冒充。
- 新格式只接受已知主版本；同主版本只允许新增向后兼容的可选字段。未知主版本、缺少安全必填事实或`future_data_used`不是明确布尔`false`时，验证失败关闭。
- 每个旧生产JSON只能有一个明确的只读适配入口。适配器不得回写旧文件、改写历史、复制大型历史数据或猜测缺失事实；不能确认的可选事实写`unknown`，不能确认的安全必填事实直接失败。
- ReleaseManifest覆盖完整生产发布包，并用`web`、`discord`、`audit`标注用途。用途不等于加载要求：网页仍只加载自身需要的轻量文件，不得因Manifest把完整历史或审计文件放进首屏。
- Manifest按时间语义分别校验：`daily_snapshot`必须与发布日一致且防未来明确为`false`；`versioned_config`不要求日期和防未来字段，只检查版本引用；`research_summary`只要求研究覆盖末日不晚于发布日并保存来源实验。
- `factor-registry.json`是`versioned_config`，其`registry_version`必须与当日因子快照和模型引用一致；不得为它伪造`as_of`或`future_data_used`。
- `decision-summary.json`是`research_summary`，不得作为扫描、评分或排行输入；Manifest仍校验其大小和SHA-256，并要求`coverage.end`不晚于发布日及`source_experiment`存在。
- M01只在测试临时目录或被Git忽略的`work/`影子生成Manifest，并使用2026-08-28现有样本验证；不得写入`public/`，不得改变当前生产JSON、网站、Discord、工作流或线上核验。
- 每日生产候选目录、真实生产Manifest、网站与Discord按同一`release_id`读取、线上逐项核验、受控切换、部署和回退演练全部属于M12，必须另行设计和批准。
