## 一、重构目标

这次重构不是为了把文件换个位置，也不是为了一次性重写所有代码。最终要得到一条完整、可复用、可检查、可回退的闭环：

```text
一份点时行情与股票池
→ 一个日线MACD门卫
→ 一个共同结构与长期状态检查
→ 一个唯一候选事件
→ 复杂多因子 / 我最喜欢形态两个独立分析器
→ 大盘与行业独立上下文
→ 交易就绪判断与模拟交易计划
→ 一本不可覆盖的事件总账
→ 历史重放、机器案例和人工复盘
→ 新假设、预登记和对照实验
→ 用户批准的新版本
→ 四个网站入口
→ 线上核验后的一个Discord出口
```

重构完成后的验收口号是：

> 一份行情、一个门卫、一个候选事件、两个选股器、三个独立顾问、一个交易计划器、一本总账、一个实验闭环、四个页面、一个Discord出口。

## 二、本轮已经冻结的六项架构选择

1. **长期资格采用双路径**：长期上涨后的健康回调，或者有客观证据的长期筑底反转。宽幅箱体与长期结构破坏不进入正式交易。
2. **回撤使用两把尺**：局部上涨波段的0.618／70%结构闸门继续保留；多年高点回撤超过70%时，只有完成客观长期筑底反转才能继续。
3. **周期职责固定**：月线判断长期方向，周线判断中期阶段，日线负责门票和入场；较大周期只给有限、可审计、必须经实验确定的确认奖励。
4. **明显风险先阻断交易**：宽幅箱体内部、持续向下跳空供给等样本保留紧凑事件，但不能进入完整模拟交易；当前人工否决优先，机器规则以后实验。
5. **20日无效退出先用于个人形态**：复杂多因子必须另做单一变量A/B实验，不能直接套用。
6. **采用原仓渐进式替换**：不做一次性大爆炸重写；新模块通过新旧输出对照后接管，旧模块确认无消费者后才退休。

这些是获准进入设计的目标，不等于精确阈值已经获得收益验证。会改变候选、排名或交易结果的部分，仍须单独预登记、实验和生产变更批准。

## 三、计算顺序与两种交易路径必须永久分开

以后文档和代码统一使用下面的说法，避免再次出现“日线先还是月线先”的争论，也避免事后用高周期确认美化早期日线信号。

### 机器节省计算的顺序

```text
全市场轻量数据检查 → 日线MACD刚金叉门票 → 只对小候选池做深度分析
```

### 复杂多因子路径A：大周期确认型

```text
月线方向已经确认 → 周线阶段已经确认 → 日线突破找入场 → 约20—30日短计划
```

### 复杂多因子路径B：小周期升级型

```text
日线先启动并建立短计划
→ 后来完整周线确认，才获得更长持仓资格
→ 后来完整月线确认，才获得100日／半年候选资格
```

日线先运行可以只是计算优化，也可以是路径B真实的第一阶段；两者必须由各周期确认日期区分。路径B不能在入场日使用未来才完成的周／月K线。路径A与路径B都属于复杂多因子，“我最喜欢形态”不受影响。

## 五、重构总原则

1. **先刻画现状，再替换**：每个旧模块先用测试固定当前输入输出，防止“重构”偷偷改变选股。
2. **结构重构与策略变化分开**：搬接口、去重复、加注释可以做行为等价对照；长期筑底、双回撤和风险阻断属于策略语义，必须另开实验与版本。
3. **每个输出只有一个负责人**：其他模块只能读取，不得复制公式。
4. **同一股票同一天只有一个事件**：两个模型的判断挂在同一事件下，不能重复算赢家。
5. **原始事实不可覆盖**：机器当时的门票、证据、排名和规则版本冻结；人工意见和后续价格只追加。
6. **后台计算，前端展示**：网站不扫描、不打分、不重建交易计划。
7. **一次只迁一个模块**：每个实现工作包预计不超过20分钟，完成即测试和对照；出现额外影响立即退回设计评审。
8. **旧代码不是按年龄删除**：必须确认入口、引用、工作流、测试、文档和实验复现全部完成迁移。
9. **所有新代码有人话注释**：说明职责、输入、输出、交易含义、防前视边界、版本兼容和阈值原因。

### 候选设计：文字闭环闸门（CR-2026-08-30-037，`design_review`）

以下是保留等待用户审核的候选治理设计，不是当前已经生效的仓库状态。拟议规则为：每个模块在实施前增加一个状态`requirements_closed`，只有同时完成以下内容才能进入代码：

- 一条从输入到输出的正常流程；
- 一张状态转换表；
- 一张冲突优先级表；
- 一份特殊情况清单；
- 一份“明确不做什么”清单；
- 输入输出样例和版本；
- 成功、失败、边界人工案例；
- 自动测试、防前视、新旧对照和回退方法；
- 所有尚未回答的问题已经得到用户选择，或被明确隔离为本版本不实施。

代码只能实现这份闭环文字。实施时发现文字没有覆盖的新情况，当前工作包立即停止，补充需求并重新让用户确认，不能由实现者临时猜规则。

未来实验不需要在当前重构阶段全部得到收益答案。只要明确标为`deferred_experiment`、生产保持原样、当前只预留版本化接口，就不阻塞行为等价重构；接口不得默认启用未来实验。

## 六、目标数据合同

模块开始重写前，先冻结以下小合同。字段名称可在对应模块设计包中微调，但职责不能改变。

| 合同 | 唯一内容 | 禁止内容 |
| --- | --- | --- |
| `MarketDataSnapshot` | `as_of`前的复权OHLCV、数据源、公司行动、完整性 | 分数、买卖结论 |
| `UniverseSnapshot` | 股票池层级、流动性、当时可交易状态、覆盖缺失 | 用今天名单回填历史 |
| `GateEvent` | MACD门票、局部回撤、多年回撤、长期状态、排除原因 | `public/factor-registry.json`当前有效集合中的深度因子、行业加分 |
| `TechnicalEvidence` | 因子ID、周期、家族、命中、证据日期、父子关系、风险 | 市场／行业冒充技术证据 |
| `ModelAssessment` | 多因子结论、个人形态结论、完成度和缺项 | 直接生成收益概率 |
| `ContextSnapshot` | 大盘、行业、热度、广度、数据可用性 | 回写技术原始分 |
| `TradePlan` | 入场、冻结支撑、止损、自然目标、R、时间规则、版本 | 用未来价格反画支撑 |
| `OpportunityEvent` | 一个事件ID下的门票、两模型、上下文、交易计划、人工决定、后续结果 | 同一股票日期复制两笔 |
| `ReleaseManifest` | 同一数据日全部公开文件、版本、哈希、审计结果 | 半套日期先发布 |
| `ExperimentRun` | 事件选择、基线、挑战者、分期、断点、结果、案例 | 复制整盘行情或覆盖旧事件 |

所有合同都必须包含：`schema_version`、`as_of`、`generated_at`、`source_version`、`future_data_used`和稳定ID。

### M05｜两个选股器

#### M05A 复杂多因子

**功能**：根据全部技术证据生成供人工复核的客观判断、命中、缺项和风险说明。

**交付**：因子事实引用、家族覆盖、父子确认、月周日证据、缺失关键条件和风险分栏；本模块不计算奖励、综合分或排行。

同时输出两种不可混淆的周期路径：

- `top_down_confirmed`：月线／周线在日线入场前已经确认；
- `bottom_up_escalating`：长期结构未破坏且月线、周线都不明确空头时，日线先发生，持仓期间周线／月线才依次确认；
- `tactical_daily`：只有日线，尚未升级；
- `timeframe_conflict`：高周期明确冲突，只能观察或阻断。

每条路径保存日、周、月首次确认日期，不能只根据当前同时命中倒推历史顺序。

周线／月线确认各自要求至少两个独立证据家族，其中至少一个是方向、价格结构或重新启动；完整周期K线收盘后才成立。

**验收**：每笔现行计划可以人工复算；同日止损与目标遵守冻结的保守顺序；未来价格不能改变信号日支撑；未批准的周期实验字段存在也不得改变生产结果。

## 八、建议时间线

时间线以“用户批准一个模块→完成小包→人工验收”为节奏。每个实现小包预计不超过20分钟；CI、回测、部署和用户人工检查不计入代码小包时间。

六周只是用于理解依赖顺序和工作量的建议窗口，不是自动实施许可，也不是固定交付承诺。M00—M13每个模块都必须先提交独立设计包并分别获得用户批准；某个模块获批不能代替其他模块的批准。

| 5 交易与总账 | 第4周 | M08—M09 | 一份TradePlan、一本OpportunityEvent账、双账迁移报告 |
| 6 回测闭环 | 第5周前半 | M10—M11 | 同检测器重放、周断点、赢家输家案例、升级闸门 |
| 7 产品出口 | 第5周后半 | M12 | 四页同源、原子发布、线上核验、Discord同源 |
| 8 退休与观察 | 第6周 | M13 | 旧依赖清零后退休；连续5个交易日影子／生产对照 |

这不是一次六周后才交付。每个模块完成后都必须有独立可验收产物；前一模块未通过，不开始下一个模块。

## 九、每个模块的固定交付模板

每次开始一个模块前，先提交对应设计包，用户明确批准后才实施：

1. 当前入口、调用者和现有输出；
2. 新模块唯一职责；
3. 输入、输出、schema版本和样例；
4. 明确改动文件与明确不改文件；
5. 新旧输出对照口径；
6. 单元、契约、集成、防前视和人工案例；
7. 数据迁移与兼容期；
8. 回退点；
9. 不超过20分钟的小工作包；
10. 测试、提交、部署和线上证据分别报告。

## 十、隐藏雷点登记

### P0｜不处理就不应开始重构

| 雷点 | 现在的危险 | 保护办法 |
| --- | --- | --- |
| 本地有大量未提交改动 | 不知道哪些是用户资产、哪些已上线 | 先做基线清单和可恢复点，不覆盖、不重置 |
| 文档版本漂移 | 37／39项、周期顺序和当前／目标混在一起 | M00统一状态标签，动态数字只从机器生成 |
| 共同结构闸门文档领先代码 | 误以为生产已经淘汰深跌股票 | 先做现状特征测试，再按独立CR实现 |
| 两本事件账同时存在 | 重复事件、不同入场与收益 | M09显式迁移和逐事件对账 |
| 每日发布不是完整单包 | Unified或Ledger失败时逻辑上可能出现半套新数据 | M01/M12引入ReleaseManifest和一次切换 |
| 自动任务会向main提交 | 重构过程中可能与机器人提交冲突 | 每包开始前同步状态；生产数据提交与重构分支明确隔离 |

### P1｜会造成错误结论或重复逻辑

| 雷点 | 现在的危险 | 保护办法 |
| --- | --- | --- |
| 旧Tracker仍被基础层引用 | 直接删除会打断行情、测试和历史脚本 | 先提取共享技术函数，再清零引用 |
| 旧Rare Radar仍被首页和Discord读取 | 两套“机会”继续并存 | Unified接管消费者后才退休Radar |
| 个人形态近千行且混V1/V2/V3 | 修改V3可能破坏历史兼容 | 当前检测器与legacy适配器分开测试 |
| 长期筑底阈值来自已见案例 | 容易为CGEM量身定制 | 案例只验收；阈值在开发样本冻结，2025/2026验证 |
| 多年回撤使用今天高点或幸存股票池 | 历史资格产生未来泄漏和幸存者偏差 | 每个`as_of`只看当时历史；分层报告退市覆盖 |
| 月／周K未完成 | 大周期方向提前知道未来 | 只使用最后完整自然周／月并保存结束日 |
| 家族重复确认与原始颗数 | 同一故事被当成多份独立Alpha | 原始、家族、父子、周期四列分开并封顶 |
| 行业成员反推行业后再给个股加分 | 自我强化循环 | 计算广度时排除自身，每日只计算一轮 |
| 人工否决覆盖机器记录 | 无法判断机器是否改善 | 人工决定只追加，机器快照不可变 |
| 新规则混入旧周回放 | 不同版本汇总成一个伪策略 | 每事件冻结版本；跨版本只分层比较 |
| 事后看到周／月确认就延长旧交易 | 直接产生未来数据和虚假长持有收益 | 只在确认K线完整收盘后的下一可执行时点升级，旧计划不可改写 |
| 把最长持仓写成必须持有 | 止损或目标已触发仍拖延退出 | 所有窗口只是上限，风险与退出始终优先 |
| 周／月确认发生在原交易结束后 | 把已经结束的交易复活 | 作为新事件／再入场候选，不延长旧事件 |

### P2｜影响可维护性与运行稳定

| 雷点 | 现在的危险 | 保护办法 |
| --- | --- | --- |
| `public`文件过大 | Cloudflare单资产限制和页面变慢 | 网站只读紧凑最新摘要，完整数据留Git |
| 历史行业成员不足 | 用今天分类解释过去 | unavailable而不是猜测 |
| 旧项目名散落 | 环境变量和运维误读 | 当前代码逐项迁移；冻结实验名不改 |
| 注释不足或注释失效 | 人工代码审查成本高 | 关键入口写职责、边界和为什么；测试注释与实现一致 |
| 一次修改跨三层以上 | 难测试、难回退 | 拆CR；若无法拆，先只改合同再逐层接入 |
| 回测依赖网络与大缓存 | 失败后浪费时间 | 缓存复用、每周落档、失败不移动断点 |

## 十一、全项目完成标准

只有同时满足以下条件，整轮重构才可以宣布完成：

- 每个生产输出有且只有一个负责人；
- 每日与历史使用同一数据读取、门卫和检测器；
- 复杂多因子与个人形态共用一个事件但保留独立判断；
- 技术、大盘、行业、人工判断和退出结果分别保存；
- 排行与交易就绪清单明确分开；
- Signal History与Opportunity Ledger完成迁移，只剩一本权威总账；
- 回测能从总账挑出赢家、输家和边界案例供人工复盘；
- 实验不能自动修改生产，新版本只在用户批准后生效；
- 四个页面只读取紧凑同日结果；
- Discord只在部署和线上核验通过后读取同一结果；
- 旧代码全部有`退休／历史只读／仍在用`结论；
- 全量测试、历史样本、人工案例、提交、部署和线上核验证据完整；
- 连续至少5个完整交易日的新旧影子输出没有未解释差异，再关闭旧生产入口。
