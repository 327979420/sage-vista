# M12｜完整生产链路最小设计

版本：`0.1.0-draft`；日期：2026-09-06；状态：`design_review`。

关联：CR-2026-09-06-053。用户仅授权准备设计，未授权M12实施、合并、部署或生产启用。设计基线为main双亲合并`14fef535f67b7c4de035b4c84224e604850f1fed`，M11治理收口提交`be1119e`另待审核。本设计不是业务规则变更或生产批准。

## 1. 一句话职责与首轮完成标准

M12把既有模块接成一条可恢复、可核验、可回退的生产链，让用户每天在现有四页看到同一完整交易日的可信结果；线上核验后Discord才读取同一份结果。M12只编排和投影，不重算因子、评分、排序、交易或收益。

优先交付一条端到端可运行的链，不先扩展看板、研究页、可视化或通用插件框架。首轮必须交付行情／股票池准备、M03—M09同源串联、已到期M10评价调度、四页轻量投影、发布Manifest、部署验证、通知及恢复演练。只包装旧JSON、只展示合成样本或只完成Manifest都不算新版生产链完成。真实上线仍需另行批准。

## 2. 已核实的当前接点

- `services/scanner/daily_tracker_update.py:run`在工作目录生成旧Tracker、因子、Radar、行业、大盘和历史，经日期校验后逐文件替换public；其单文件替换不等于整个包在故障中保持原子可见。
- `.github/workflows/daily-eod.yml`继续负责正式EOD、后续Unified／总账、测试、部署、核验和通知。现有Cloudflare定时、GitHub备用、恢复触发必须复用此入口，不能新开第二套生产调度。
- `services/scanner/factor_snapshot.py`已有M03—M10影子接点；`services/market_data/consumer.py`及现有影子存储保留非生产写入保护。不能通过删除保护或给影子目录改名来启用生产。
- `services/contracts/manifest.py`仅构建／写入／校验`ReleaseManifest 1.0.0`、`shadow_only=true`，固定旧文件集；不是生产Manifest。新版本必须在原唯一合同校验入口增加明确分支，旧合同保持只读／影子边界。
- `services/market_data/universe.py:build_forward_universe_snapshot`已有3.x前向formal构造入口，但真实完整成员、稳定观测身份、逐项资格和生效日须有外部来源证据；不能把当前ticker列表倒填历史。M06仍要求可靠带日期成员映射。
- `services/ranking/producer.py`的authoritative输出需要精确政策和生效日的activation。M11的`LifecycleAuthorityResolver`必须消费可信批准／main实现／M12证明，不能沿用合成test解析器作为生产授权。
- `verify_live_deployment.py`已核验多份数据与日期；`discord_daily_digest.py`仍有旧Radar回退路径。新版必须用同一个固定发布包，不能在缺权威排行时自行重排。
- 旧行业程序已有按日期选择FinanceDatabase快照的消费者；这不构成新版M06 formal成员证据。

## 3. 建议唯一链路

```text
现有daily-eod统一触发（显式模式、as_of、版本配置）
→ M02一次准备行情、股票池和来源身份
→ M03 Gate → M04技术事实 → M05两模型
→ M06市场／行业上下文 → M07唯一权威排行
→ M08计划／退出 → M09不可变总账
→ M10更新已到期结果（未成熟保持pending，不阻塞当天扫描）
→ M12只读生成四页投影与通知候选 → 完整发布包＋Manifest
→ 合同／日期／身份／测试／构建检查
→ 部署不可变版本 → 线上核验完整包
→ 保存可信发布收据／切换已验证版本 → Discord幂等发送
```

新中立负责人建议为`services/publication/`：编排、发布包投影、收据、通知计划；行情与业务计算继续调用各模块唯一入口。扫描和回放共用相同模块纯函数；模式和as_of显式传入，回放不部署、不通知。M11只读提供四轴状态；策略晋级不是每天EOD的自动副作用。

## 4. 输入输出与合同最小边界

输入为完整收盘日期、完整40位代码提交、版本化生产配置、批准与生效日、M02不可变来源以及M03—M11稳定ID／内容指纹。配置冻结股票池、数据源、各模块政策版本、必需文件和消费者；不得在UI或工作流散落业务默认值。

建议扩展唯一`services/contracts/validation.py`的`ReleaseManifest 2.0.0`版本分支。保存发布ID／内容指纹、as_of、代码提交、配置／批准引用、模块版本及输入集合指纹、逐文件路径／大小／SHA-256／角色／合同版本／时间类别、前序发布引用。内容寻址身份包括代码、配置及完整文件集合。仅每日结果要求统一as_of，注册表与历史摘要分别遵守版本和coverage_end边界；不得机械把所有日期都改成当天。

发布文件集按现有四页实际消费者冻结，审计原件与大历史留在私有不可变账本，不随站点下载。保留现有页面路由与必要兼容投影；投影只读取冻结结果，不能把缺字段补成推测值或重算排名。版本化目录中保存完整Manifest和公开文件，客户端一次锁定release_id，后续读取该版本，避免跨版本混读；当前版本入口只在完整包就绪时切换。

发布验证收据保存release_id、部署ID／提交、环境、实际下载文件哈希、页面验证结果与时间；通知收据保存同一release_id、事件／状态去重键与发送结果。由可信流水线证据产生，调用者自填“成功”不是证明。M12收据与M11既有激活事件分别保存，不创造另一套策略状态。

实施A包前必须在设计中列出上述2.0合同的精确字段、允许枚举、身份公式、单一验证入口和固定四页文件映射，送审补齐；本稿不授权以未冻结字段直接编码。

## 5. 首次启用与真实数据门槛

- 起点选部署批准后有完整真实来源的首个收盘日。M02股票池必须能被现有formal合同接受；M06缺稳定成员身份时明确unavailable。对于配置声明必需的证据缺失，整个候选包失败关闭；可选上下文缺失仅显示缺失，不伪造支持。
- 首次新旧差异预览必须逐项列明候选池、因子、模型、排行、交易计划和数据覆盖。模型／评分／退出版本不能因模块已进入main而自动成为生产版本；权威M07版本必须另有精确批准与生效日。
- 现行已批准生产基线保持legacy身份，作为明确标记的对照及回退版本；不得补标M11 validated或用它豁免新策略闸门。新策略active仍需M11 validated、用户批准、main实现和可信M12证明齐全。
- 无策略满足上述条件时仍可预览新链的研究候选、风险及缺失状态；不能上线宣称新策略active。上线批准应明确发布模式、研究候选与策略active边界，避免“为了尽快可用”降低证据要求。
- 首次真实来源采集、费用／权限、生产存储位置及可靠成员证据都须在上线卡中确认，不在本轮访问行情或生成生产身份。

## 6. 幂等、失败与回退

同一日期／生产配置只允许一个进行中的发布；所有触发共享锁和检查点。输入未变重试复用原包，内容冲突失败关闭。扫描／评价／发布失败记录永久保存；失败不得移动夜间断点或改写已冻结事件。

发布前失败保留上一完整版本；部署后核验失败禁止通知并恢复上一已验证版本，保存失败收据。已上线通知失败仅重试通知，不重新扫描或重新部署。网络发送结果不确定时保留`uncertain`并停止自动重发该键，先核对平台回执；不承诺跨网络恰好一次送达。

策略激活与停用均通过M11追加事件；网站版本回退不能删除策略历史或自动把retired策略复活。退回旧发布包也必须重新核验其线上字节。保留旧入口作为明确关闭的回退通道，任一时刻只有一个权威生产入口；删除旧代码留给M13。

## 7. 范围与最小工作包

允许设计涉及：`services/publication/`、既有Manifest唯一验证入口、模块生产编排与受保护的正式存储入口、四页读取器、现有daily-eod／部署／验证／Discord接点及对应合同测试。对上游只新增必要编排适配，不改业务算法、稳定身份公式、阈值、历史版本或保护规则。需要改变上游合同或业务语义时另列最小依赖设计并重新评审，不能在消费者复制校验。

不做：新看板、研究中心、完整历史下载、参数搜索、真实多年回测、自动策略晋级、VectorBT、M13删除、CR-043新功能。周期持仓升级等未实施业务只能显示实际状态，不伪造UI功能。行业快照和LICENSE保持原字节。

## 8. 核心验收

1. 相同输入按每日和回放得到相同业务身份；回放无发布副作用。
2. 缺股票池／成员／日期／身份／批准、future_data或未知版本失败关闭；不降级伪formal。
3. 四页与通知的股票、顺序、理由、日期、版本均来自同一Manifest；大历史不进入首屏。
4. 写入一半中断、并发触发、缺文件／错哈希／混日期／旧缓存都不产生已验证发布。
5. 线上验证实际文件字节与Manifest一致；失败不通知，恢复上一完整包。
6. 通知失败不重跑业务，重复／不确定请求留证且不盲目重发。
7. M11状态与M12证明一致，无test解析器或自签权限旁路；未validated不变active。
8. 旧结果、策略、回测断点及FinanceDatabase快照／许可不变；治理状态不冒充上线。
9. 实施时运行相关Python、前端构建／渲染和工作流契约测试；上线时另做真实收据和在线核验。
