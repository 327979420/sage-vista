# Sage Vista 总规则手册

文档版本：`1.6.0`
规则状态：项目总入口与精简摘要
最后更新：2026-08-28

> 本文件只回答“整个系统怎样协同”。具体规则只在对应模块文件维护，避免一项改动需要重读或改写整本手册。

## 1. 项目宗旨

Sage Vista 要成为一套能够长期积累、验证并执行个人交易经验的交易研究系统：

1. **交易知识库**：系统总结技术面、基本面、行业和大盘经验，不让经验只存在于记忆和聊天中。
2. **机械化决策助手**：把可定义的判断变成一致规则，减少恐惧、贪婪、追涨和临时改口径等个人情绪。
3. **选股器**：先从全市场找到符合用户重视的交易形态的股票，让精力集中在少量真正值得研究的标的上。
4. **多因子研究系统**：从真实经验出发，用回测、独立验证和持续前向跟踪寻找有效因子与有效组合。
5. **可进化交易系统**：每次实验、成功、失败和真实交易教训都要留档；有效打法进入“策略宝典”，明确且重复出现的亏损教训进入“交易红线”。
6. **可用的网站产品**：网站是最终交付成品，必须直接回答今天看什么、为什么、风险是什么、历史是否有效，而不是只展示工程数据。

当前建设顺序是：**先把技术面交易形态、扫描、评分、追踪和回测做扎实；再逐步精进行业、大盘与基本面；最后持续把验证结论变成更好用的网站和更机械化的决策流程。**

## 2. 一句话原则

Sage Vista 以多因子模型为主线：**大周期看方向，小周期找时机；日线 MACD 负责触发，月线优先于周线，周线优先于日线；技术形态负责选股，大盘和行业负责调整优先级与风险；每次真实触发和每次实验都永久保存，用后续结果持续改进系统。**

项目是研究与人工决策工具，不自动下单，不把规则匹配分数写成收益概率。

日线 MACD 是进入研究池的“门票”；触发后按照**月线 → 周线 → 日线**从大周期到小周期扫描关键交易信号。大周期决定方向和主要研究窗口，小周期负责择时。

**评分负责入场，退出机制负责持仓。** 入场后的日 / 周 / 月观察窗只是最长研究范围；任何已经验证、批准并启用的止损或退出条件，都优先于原始高分和周期标签，并在最早可执行时点退出。

## 4. 全系统流程

```text
完整美股收盘数据
→ 大盘环境
→ 日线 MACD 当日触发
→ 月 / 周 / 日技术因子检测
→ 技术候选分
→ 行业与大盘调整
→ 统一排行榜
→ 精选机会（排行榜严格子集）
→ 入场后独立监测风险与退出条件
→ 永久追踪与实验评价
→ 网站发布和通知
```

技术扫描始终保存事实。大盘和行业只调整优先级、风险和人工决策，不删除技术信号。

## 5. 当前与目标边界

### 当前已上线

- 统一因子库 `0.8.0`，共 37 个因子。
- 日线 MACD 当日金叉触发其余 36 个因子的深度检测。
- 当前正式候选排序仍使用 Unified V2 技术公式；周线/月线 EMA 与吞没暂在实验观察层。
- 技术分、行业调整、大盘调整分开保存，再形成最终优先级。
- 信号和实验应保留版本、日期、因子状态与后续结果。

### 已批准、尚待完整验证或实现

- 同类证据按月线高于周线、周线高于日线研究。
- 输出主导周期，并用日 / 周 / 月不同窗口评价和管理持仓。
- 补齐适用的周线/月线 FVG 和高周期支撑。
- 用多年、独立验证和前向数据决定哪些实验因子能进入正式分。

精确公式与状态不得写在总手册重复维护；以模块文件为准。

## 6. 改动总原则

1. 新对话先读交接入口和机器生成的当前状态，再定位模块；旧聊天只作背景，不作权威事实。
2. 用户的每个新想法先进入需求账本。尚未清晰或尚未批准的碎片只记录，不直接变成生产规则。
3. 先按`docs/CHANGE_WORKFLOW_ZH.md`说明当前流程、目标接入点、输入输出、影响范围、验收和回退；用户明确批准设计包前，不允许编辑业务代码。
4. 获批后先修改该模块规则、版本和变更记录，再修改代码；没有完成文字规则，不允许开始语义代码改动。
5. 跨模块改动只修改真正受影响的模块；总手册只在模块边界或全局原则改变时升级。
6. 影响选择、评分或交易结果的改动，先在实验模块登记对照方案。
7. 实现必须拆成预计不超过20分钟、可独立验收的小包；范围扩大时停止并重新进行架构评审。
8. 再测试、回测、永久留档、更新 UI、部署和线上核验，并把证据写回需求账本。
9. 聊天中的想法未写入相应规则或需求账本前，不算长期项目内容。

## 7. 权威入口

发生冲突时按以下顺序处理：

1. 对应的 `docs/rules/*.md` 模块规则；
2. 本总手册中的全局边界；
3. `docs/DECISION_LOG_ZH.md` 中带日期的已批准决定；
4. 因子注册表、实验账本和版本化产物等机器事实；
5. 代码与测试代表的当前实现；
6. UI 文案；
7. 聊天内容。

如果规则与代码不一致，必须明确标为“规则目标”或“当前实现”，不能假装已经上线。
