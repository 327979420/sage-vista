# SV Trading Foundation V0｜让候选进入一套能对账的模拟账户

日期：2026-09-16。状态：每日账本已实现并通过本地测试；真实历史复现待运行，完整V0尚未验收。
战略来源：[用户路线图](../SV_DEVELOPMENT_ROADMAP.md)。研究规则仍由[规则08](../rules/08_BACKTEST_AND_EXPERIMENTS.md)维护；实际进度只记[需求账本](../CHANGE_REQUESTS_ZH.md)。

## 目标

回答一个问题：给系统10万美元，按一组事先写好的买卖规则，逐日交易后，钱和股票到底变成多少？
先验证账户能正确运作，再判断策略好不好。选股器暂时保持；现有选股表现不错是产品判断，不是已证实的稳定盈利。

## 假设

复用已有账户和执行基础，补齐新版信号接入、明确交易状态与每日明细，比再建一套引擎更快获得可检验的账户结果。完成本轮不要求收益为正，也不代表正式策略获准使用。

| VectorBT | [Portfolio](https://vectorbt.dev/api/portfolio/base/)：现金、订单与组合模拟 | 继续沿已有适配；固定版本，用同一订单流核对账户 |

这是本轮适配选择，不按GitHub星数挑策略，不借用外部买卖信号。引入新依赖前另查许可证与版本兼容性。

## 范围与数据对象

保留研究引擎与交易引擎的逻辑分离，交易逻辑不放进页面。

| 对象 | 必须能说明什么 | 复用或补充 |
| --- | --- | --- |
| Signal / TickerCandidate | 股票、事件、机会周期、当时分数、可知时间、原数据身份 | 原冻结事件的适配视图，不能读取outcomes来决定下单 |
| TradeProposal | 何时允许买、排序原因、投入上限、入场/退出版本 | 优先扩展现有TradePlan合同；排名与仓位金额分开 |
| Order / Fill | 提交时间、成交时间、数量、价格、费用、拒绝原因 | 衔接现有VectorBT订单；拒绝或未成交不能变成持仓 |
| Position / ClosedTrade | 股数、成本、已实现与未实现盈亏、机会周期 | 持仓、订单、研究候选不混为一个状态 |
| DailyPortfolioSnapshot | 当日现金、持仓市值、总资产、持仓数、占用比例 | 从同一次账户计算导出，不能另算第二套净值 |
| PerformanceSummary | 账户指标与逐笔交易指标 | 两类分开标注，报告给中文解释 |

先支持历史模拟长仓、单币种、整股、无杠杆。状态明确包括候选、已提案、待成交、已成交、持仓、待退出、已关闭，以及拒绝/过期；状态时间只能前进。

## 里程碑与交付

1. **接线与合同**：明确输入、机会周期和执行配置；小样本顺序回放，显示每笔“为什么买或没买”。
2. **账户闭环**：保存每日现金、持仓、买卖、费用和净值；生成第一条可复现账户曲线。
3. **账务验收**：手算例子和相同订单流的参考实现一致，再跑冻结真实候选。20年候选是观察事件流，未证明覆盖全部可交易信号；结果必须叫“冻结候选账户实验”。
4. **绩效验收**：总收益、CAGR、年化波动、Sharpe、Sortino、最大回撤、暴露/资金利用率及基本逐笔交易统计。补齐盈亏比、profit factor、expectancy、持仓时长、连胜连败、已实现/未实现盈亏。行业缺数据就标缺失。

10万美元可作为工程基准。旧账户10%初始资金/笔、最多10只、单边0.1%成本有legacy授权，但不能自动成为新策略最优参数。V0工程基线固定单一方案用于验账，入场和分周期持有配置在实现前登记；随后原五轮实验逐项替换，不能同时优化仓位和退出。

## 验收标准

- 每日总资产 = 现金 + 各持仓市值；无杠杆时现金不得负数，成交费用只能记一次。
- 所有下单信息在决定时已经可知。收盘确认不能用当天早已发生的开盘成交。
- 拒绝、重复信号、满仓、现金不足、未成交、未平仓都保留明细；改变未来行情不改变过去订单。
- 订单执行顺序固定；卖出释放的现金何时可用于新买入必须明确，不能根据当天最终结果选顺序。
- 日内同时碰止损/止盈不猜价格先后；使用预先登记的保守处理或标记歧义。
- 同一输入与版本重跑，订单、费用和每日账户一致；重启不重复成交。
- 账务金额按声明的舍入规则核对到美分；收益率公式按预先冻结容差核对参考实现。
- 年化交易天数、CAGR时间口径、无风险利率、Sortino目标、回撤起点、费用/滑点口径明写；零交易、零波动、没有亏损等边界不能输出伪造有限数值。
- 未实现盈亏不能混成已平仓收益；未平仓头寸纳入账户市值；基准使用同一日期和价格口径。
- 未证明历史覆盖、复权/公司行动处理、退市或持仓价格完整性时，不声称全市场正式20年策略绩效。

## 依赖

既有版本锁、冻结收据/原行情、交易日历、明确执行配置、原账户测试及少量可手算样例。优先恢复已有缓存和逐股断点。若使用复权价格模拟股数，必须说明其研究口径，不能另加股息造成重复计入；原始价格与公司行动账务另作明确选择。

## 不在本轮做

新因子、选股器重写、机器学习、多个引擎迁移、几十种退出组合、券商API、真实资金交易、整站改版。Alpha/beta与滚动分析后续增加；实盘功能按影子账户→纸面交易→小资金的路线推进，路线图不是实盘授权。

## 实验记录与决定

每项买卖研究沿原账本记录假设、变化、数据、基线、指标、失败条件、结果及采用/拒绝/资料不足。负结果保留。本轮成功标准是“账正确、过程可复现”，不是挑到最高收益；账户基础与策略有效性分别验收。

## 本轮实际交付与剩余事项

- 复用原VectorBT订单和共享现金；新增独立账本导出器，逐日核对现金、持股数、总资产。没有重新选择交易或重扫20年股票。
- 买入回调即时保存当时现金、持仓数和拒绝原因；原收盘信号最早下一交易日开盘执行。同日卖出款不能反过来资助早先的开盘买入。
- 原账户执行入口自动输出JSON和中文每日账本，并把账本放进原不可变收据和报告。支持原日期区间接口。
- 复用QuantStats收益、年化、风险指标；手算核对CAGR、波动、Sharpe和Sortino。已卖出与未卖出盈亏分开，记录换手、胜负、资金占用；行业数据缺失明确保留。
