## 人话版

现在的行情像放在同一个大抽屉里，但很多人都有钥匙：每日程序会往里面补数据，市场ETF程序会自己刷新，研究程序发现没有文件就重新下载，旧Tracker还会把长期文件裁成最近约2200根。每日和回测都写着使用`work/eodhd-cache`，不等于它们真的经过同一个仓库管理员，也不保证拿到的是同一版本。

股票池的问题也类似。今天的扫描主要看“现在仍活跃、今天有成交、而且本地正好已有历史缓存”的股票。这个集合没有稳定版本，不能拿来回答“2020年那天机器当时会看到哪些股票”。如果把今天还活着的名单倒放到历史，就会漏掉后来退市的失败者。

M02准备增加一个唯一的行情仓入口和一本很小的股票池名册：

1. 行情只由仓库入口下载、合并、校验和保存；其他程序只能读取。
2. 每日和回测向同一个入口说清楚“我要哪一天以前的数据”。
3. 股票池按版本和生效日保存；不知道历史成员时明确说不知道，不能拿今天名单冒充。
4. 缓存只补缺口，不重复下载已有范围；读取窗口在内存中裁剪，不能把长期原件裁短。
5. 每次读取都证明返回的最晚日期不超过`as_of`，因此历史程序看不到未来。

M02不会改变MACD、因子、评分、排行榜、形态、持仓或交易结论。实施时必须先做影子对照；在新旧行情、股票池数量和MACD结果逐项一致前，现有生产入口保持不动。

## 包D本地成果（已测试并由独立本地提交保存）

- 新增唯一`MarketDataRepository`，缓存根目录和数据源都必须由调用者注入；包D没有任何EODHD、网络、Git、扫描器、回测器或`work/eodhd-cache`入口。
- 仓库文件名只从规范`instrument:sha256:<64位小写十六进制>`稳定ID派生；绝对路径、目录穿越、Windows路径、反斜杠和非规范ID在访问数据源或创建行情文件前失败。
- 调用者必须显式提供`as_of`和需要的日期。完整命中时数据源调用为0；头部、尾部或中间缺口只把缺少日期交给注入数据源，重复运行不重复补齐。
- 同一证券同时被多个线程或仓库实例请求时，先使用进程内锁，再使用按稳定ID派生的文件锁；取得锁后重新读取缓存，因此同一缺口只执行一次实际补齐。
- 仓库先完整验证注入新行和合并后全历史，再在同目录写临时文件、刷新到磁盘、重新读取验证，最后原子替换。替换前任何异常都会删除临时文件并保持旧缓存字节不变。
- 旧日期默认不可覆盖，完整历史不可裁短。只有调用者显式列入`refresh_dates`的日期才允许比较供应商修订；数据源返回未请求日期、漏日期、非法行或试图夹带旧日期时整次拒绝。
- 修订记录与单份完整行情保存在同一个原子状态文件中，逻辑上只追加。每条记录保存稳定证券ID、变化日期、完整旧行和新行、变化前后全历史指纹、上一修订ID与指纹、当前修订指纹及`reconstructible/not_reconstructible`状态；后一状态必须有明确原因。
- 历史读取只返回`as_of`及以前的复权行和点时指纹，不向消费者暴露包含未来行的完整缓存指纹或修订日志，避免元数据泄漏未来状态。

### 前向正式股票池冻结设计（F— I实施前提）

- 正式股票池只从未来第一个“完整成功保存”的交易日开始；不回填2026-08-28或更早日期。历史缺失继续返回`universe_unavailable`，不能自动退回旧名单。
- 每个正式交易日必须保存权威完整来源成员，以及每名成员同日的纳入或排除证据。成员来源不完整、身份冲突或任何成员缺少资格结论时，整日正式快照失败关闭。
- 前向证券身份使用`provider`、`market`、`exchange`、`provider_code`和`observed_listing_epoch`。观察纪元只是系统第一次完整观察到该上市实体的日期，不是IPO日期；ISIN只作辅助证据，缺少ISIN不能单独决定纳入或排除。
- 消失后重新出现、交易所变化、供应商明确重上市或身份冲突时建立新epoch和新证券ID；旧身份不覆盖。身份依据必须随快照保存为可审计字段，不能只保留一个无法解释的哈希。
- 既有`UniverseSnapshot 2.0.0`没有上述必填身份依据与完整来源证明。新正式结构因此使用`3.x`主版本，旧`2.x`含义保持不变并继续只读验证，禁止静默升级。
- 旧每日与回测数据继续归为`legacy`，可用于兼容研究，但必须保存幸存者偏差和成员证据不完整标签。formal与legacy只能显式选择；formal缺失不得自动回退。

尚未解决的证据风险：没有未来首个完整生产日快照；没有全市场真实缓存可做逐股OHLCV等价；现有默认每日、夜间与研究消费者仍直读旧入口；2026-08-28及更早日期仍没有formal股票池。它们必须保持显式缺口，不能由M02本地测试推断完成。

### A—C后续人工审计修复

用户抽查代码后又构造了三类反例，原测试没有覆盖：标成`legacy`但自称覆盖完整的股票池仍可能被formal选择器接收；只带`instrument:sha256:`前缀、后面不是完整哈希的证券ID仍通过；截止日之后一根缺字段的坏K线会反过来阻断更早日期的点时读取。`CR-2026-08-31-041`已经在独立本地修复分支处理这三项：formal和legacy按路径身份严格隔离；证券ID必须完整匹配64位小写SHA-256；完整缓存写入仍验证全部OHLCV，但历史读取只让`as_of`及以前的OHLCV参与结果，整份日期轴仍须规范、唯一且有序。

## 四、行情仓设计

### 1. 不复制整盘历史

M02区分三层，但只保留一份完整价格历史：

1. **原始权威缓存**：按稳定证券身份保存EODHD原始日线，是可再生成的本地/CI资产，不进入Git和网站。
2. **小型元数据**：保存来源、结构版本、覆盖起止、行数、最后核验时间、内容SHA-256、数据修订号和公司行动检查结果。
3. **点时复权视图**：调用时从原始缓存生成，只返回`as_of`及以前的行；默认不再落一份完整副本。确需提速的派生缓存必须能由原始缓存重建并带独立指纹。

旧`work/eodhd-cache/*.json`在迁移期只读适配，不复制一套大型历史。适配验证通过后可以原地由新仓库接管其格式，或者按用户批准的迁移方案移动一次；本设计不执行移动。

### 2. 证券身份

- 新仓库存储键不能只用ticker。最低身份应包含提供者、交易所/市场、提供者代码和上市生命周期标识。
- 如果提供者没有足够证据区分ticker复用，状态写`identity_unknown`并隔离，不能把两段历史猜成同一家公司。
- 展示ticker可以变化；稳定证券身份、原ticker和变更证据必须保留。
- 前向正式身份明确使用`provider + market + exchange + provider_code + observed_listing_epoch`。`observed_listing_epoch`是系统首次完整观察到该上市实体的日期，不是IPO日期；ISIN只作辅助证据。
- 消失后重现、交易所变化、供应商明确重上市或身份冲突时，必须建立新epoch和新证券ID。快照保存上述原始依据和身份来源，不能只留下哈希。

### 3. 缓存键

为避免“把股票池版本塞进价格文件而复制历史”，分成两种键：

- **原始行情分片键**：`provider + market + instrument_id + raw_schema_version`。
- **点时准备结果键/快照ID**：`provider + raw_revision + adjustment_policy_version + universe_id + as_of + contract_schema_version`。

这样同一只股票的价格只保存一次，但“哪一版股票池、哪一天、哪种复权口径”仍能得到唯一可追溯的`MarketDataSnapshot`。

### 4. 命中、补缺和修订

1. 先读元数据，算出请求范围与已有覆盖的差集。
2. 完整命中时网络调用必须为0。
3. 部分命中时只请求缺失头部或尾部；不得因为要2026-08-28就重下2000年以来全部历史。
4. 对供应商可能回改的近期窗口做有界复核；发现旧行变化时记录数据修订号和变更日期，不能静默覆盖后仍声称是旧指纹。
5. 公司行动导致早期复权值变化时，按冻结政策重算视图并记录修订；实验和回放保存所用数据修订指纹。
6. 下载、解析或校验失败时不动旧文件；使用临时文件、`fsync`和原子替换。
7. 同一分片使用锁或single-flight，多个消费者同时请求时只能有一个下载者，其余复用结果。
8. 空结果和提供者限流只能做短期负缓存，必须记录原因与失效时间，不能永久假装该股票没有数据。

### 5. 数据完整性

每个分片至少检查：

- 日期严格为`YYYY-MM-DD`、升序且不重复；
- OHLC为有限正数，`low <= open/close <= high`；
- 成交量非负；
- 调整所需字段存在；
- 返回日期不得晚于请求上限；
- 覆盖、行数和SHA-256与元数据一致；
- 数据源和结构主版本为已知值。

缺字段或身份冲突不能自动填0或猜值。该证券在本次快照中标为不可用，并给出机器可读原因；达到关键覆盖阈值时整次准备失败关闭。

## 五、股票池版本化设计

### 1. 两类事实分开

- **成员事实**：某证券在某版本股票池中是否存在，来源和生效日是什么。
- **当日资格事实**：在`as_of`当天是否有完整价格、股价是否不低于5美元、成交额是否不低于1000万美元、历史是否至少420行。

成员版本不能用当天价格重新命名；当天资格也不能改写原成员名单。`UniverseSnapshot`应保存二者及逐项排除原因。

### 2. 版本与层级

第一版沿用总需求中的层级：`core`、`main`、`extended`、`small_cap`、`delisted`。每个快照至少保存：

- `universe_id`、`schema_version`、`eligibility_rule_version`；
- `effective_from`、`as_of`、来源和生成时间；
- 稳定证券ID、当时ticker、listing status；
- 所属层级；
- 纳入/排除理由；
- 成员数量、可用数量、内容哈希；
- `future_data_used=false`。

版本变化规则：成员源、交易所范围、证券类型、退市处理、流动性阈值或稳定身份算法变化时建立新版本；同一版本只追加新的生效快照，不覆盖旧日事实。

现有`UniverseSnapshot 2.0.0`继续按原语义只读验证。未来正式前向快照使用`3.x`，因为它新增了不可缺少的观察身份和完整成员来源证明：

- 完整成员来源的标识、日期、成员数和内容指纹；
- 每个成员可审计的`provider`、`market`、`exchange`、`provider_code`与`observed_listing_epoch`；
- 每个成员同日明确的纳入或排除证据。

任一必填事实缺失都不能生成formal快照；不得把旧`2.x`文件按新语义解释。

### 3. 历史点时规则

- 成员事实可以选择`effective_from <= as_of`的已知版本；资格事实必须与查询日具有完全相同的`as_of`，不能延用旧日资格。
- 不存在符合条件的快照时返回`universe_unavailable`并失败关闭该生产式回放；研究可明确记录缺口，但不能拿当前名单代替。
- 退市证券按当时是否存在和可交易判断，不因后来退市而从历史删除。
- listing status只用于覆盖审计，除非当日可交易事实有点时证据；不能用后来退市身份改变当日信号。
- 当前活跃名单不能向过去回填；行业模块已有的点时成员选择方式可作为实现范例。

### 4. 第一期历史覆盖边界

现有仓库没有完整的历史股票池快照，当前研究也公开承认退市覆盖不完整。因此M02不能把2000年以来完整点时股票池写成已实现事实。

候选迁移顺序是：

1. 未来取得真实证据后，只有每个已观察成员都具有可靠稳定证券身份和listing生命周期，才可冻结2026-08-28的`legacy_observed`快照；否则只保存原始审计证据并维持`universe_unavailable`。不得根据公开计数、缓存文件名或触发名单伪造成员。
2. 从未来第一个完整成功保存的交易日起每天追加真实快照，建立可靠前向历史；不回填2026-08-28或更早日期。
3. 已有退市样本和历史面板只读接入并标明覆盖层级、来源和缺口。
4. 2000年以来完整历史成员补齐若需要新数据源，另开数据采集设计和授权；在此之前明确披露幸存者偏差。

## 六、防未来的强制接口

### 1. 查询必须带`as_of`

生产与历史共同使用类似下面的语义；名称只是设计，不是本轮代码：

```text
repository.read_bars(instrument_id, as_of, adjustment_policy, start=None)
repository.read_universe(universe_id, as_of)
repository.prepare_snapshot(universe_id, as_of, adjustment_policy)
```

- `as_of`必填且为规范日期；不允许用“缓存最后一行”默认为历史截止日。
- 返回行情最大日期必须`<= as_of`，并在`MarketDataSnapshot`记录实际最大日期。
- 当日扫描还必须要求关键证券最后一行恰好等于权威完整交易日。
- 回测可以读取未来收益来评价已经冻结的事件，但选择、门票、因子、股票池和上下文的输入视图必须在信号时点截断。两类读取接口必须分名，不能把`selection_view`和`outcome_view`混在一起。
- 周/月线由调用层从已经截断的日线视图聚合，并继续只使用完整收盘周期。

### 2. 双重证明

防未来不能只相信输出里手写的`future_data_used=false`：

1. 仓库层结构性裁剪并返回`max_returned_date`。
2. 合同验证器检查`max_returned_date <= as_of`和明确的`future_data_used=false`。
3. 测试向底层缓存故意放入未来行，确认消费者永远收不到。
4. 回测记录股票池快照ID、行情快照ID和数据修订指纹，便于复现。

## 七、每日与回测怎样共用

### 1. 共用的内容

- 同一个Provider Adapter；
- 同一个原始行情仓；
- 同一个复权政策；
- 同一个点时读取接口；
- 同一个`UniverseSnapshot`读取规则；
- 同一套结构、完整性和防未来验证；
- 同一个缓存命中/补缺/原子写入实现。

### 2. 保持不同的内容

- 每日需要“权威日必须完整、当日成员和当日资格全部到齐”；
- 回测需要“按每个历史日重放，并把未来收益读取与信号选择读取分开”；
- 每日输出当前生产JSON；回测输出研究检查点，二者不互相覆盖；
- 每日活跃池不自动等于历史退市池。

所以“共用同一份行情”不是把所有任务塞进一个大函数，而是让不同任务向同一个只读仓库接口提出不同、明确的查询。

## 八、兼容与迁移

### 1. 影子期

- 旧`work/eodhd-cache`和`work/eodhd-bulk`继续原样运行，新仓库只读适配现有样本。
- 用固定小样本和完整2026-08-28生产样本比较新旧复权OHLCV、资格数量、31只MACD触发及公开结果身份。
- 任何不一致先报告到迁移审计，不自动采用新值。
- 影子期不写`public/`，不改每日或夜间工作流。

### 2. 逐消费者迁移

迁移顺序建议：纯转换与仓库测试 → 股票池快照 → `factor_snapshot` → Tracker → 市场ETF/行业 → `unified_v2_scan`和回测入口。一次只迁一个读取者，并保留旧入口对照。

迁移完成前禁止：

- 删除旧缓存；
- 批量改写历史JSON；
- 把现有ticker文件猜成稳定证券身份；
- 让新旧两层同时写同一个缓存文件；
- 因重构顺手改变生产候选数量或历史结果。

### 3. 工作流缓存

只有本地仓库语义和测试稳定后，才修改Actions缓存：

- 缓存身份绑定行情仓结构主版本、提供者、原始数据政策和股票池策略主版本；
- 覆盖日、数据修订和内容指纹写在仓库元数据中，不靠模糊恢复前缀猜；
- 每日和夜间使用同一逻辑身份，完整命中不下载，缺口只补一次；
- bulk日文件纳入同一缓存政策；
- Actions缓存只是加速副本，不是永久权威账本，丢失后可从提供者重建。

工作流修改属于M02后续单独批准的小包；本设计不执行。

## 十、测试与验收设计

### 1. 仓库单元测试

- 完整缓存命中时提供者调用次数为0。
- 只缺尾部、头部或中间日期时只请求缺口，不重下完整历史。
- 两个相同并发请求只执行一次下载。
- 下载失败、JSON损坏、重复日期、非法OHLC或哈希不一致时旧文件字节完全不变。
- 临时文件写完并验证后才原子替换。
- 不同数据源、复权政策、结构主版本或证券身份不会误命中同一缓存。
- ticker复用且身份不足时失败，不静默合并。
- 空结果负缓存到期后可以重试。

### 2. 防未来测试

- 底层文件故意包含`as_of`之后的行，`selection_view`仍只返回当日及以前。
- 缺`as_of`、非法日期或返回最大日期晚于`as_of`时失败。
- 周线/月线只看到已经完成的周期。
- 选择视图不能调用未来收益接口；结果评价接口不能回流门票、因子或排行。
- 同一历史日多次读取获得相同快照ID和字节级相同OHLCV。

### 3. 股票池测试

- 同一成员和规则重复生成得到同一`universe_id`。
- 成员、来源、阈值或规则版本变化会生成新ID且不覆盖旧快照。
- 历史日期选择生效日不晚于它的最新快照。
- 只有未来快照时返回不可用，不能回填。
- 后来退市的证券仍可存在于其当时快照；后来退市身份不能改变当时资格。
- 缺历史成员证据时明确`unknown/unavailable`，不能用当前活跃名单。

### 4. 行为等价与集成验收

- 对固定证券样本逐日比较原始和复权后的open/high/low/close/volume、行数、首末日期和内容哈希。
- 2026-08-28行为等价比较使用筛选后`universe_eligible_count=1337`、31只MACD触发、每只触发日期和价格；这些是结果基线，不是完整成员证据。任何差异必须逐项解释并经用户批准，不能视为重构成功。
- 每日与回测对同一`universe_id + as_of + adjustment_policy`得到相同`MarketDataSnapshot`身份。
- 旧缓存适配器只读，运行前后原文件字节相同。
- 现有Python测试、编译检查、固定防未来反例和补丁格式检查通过。
- M02实现阶段未获生产许可前，`public/`、`automation/`、网站、Discord和历史回测结果的哈希保持不变。

## 十一、失败关闭与回退

- 新仓库读取、身份、日期、版本、覆盖或哈希任何一项不可信时，影子验收失败；现有生产入口继续工作。
- 迁移开关按消费者独立，出现差异只退回该消费者，不回滚或删除旧行情。
- 在全部读取者迁移、对照通过并得到用户批准前，旧入口保持只读兼容。
- 不用`git reset`或删除缓存回退；通过版本化入口开关恢复旧读取路径。
- 股票池历史缺口以`unavailable`保留，不能为追求“测试通过”制造假快照。
- 如果供应商历史修订导致结果变化，保存新旧指纹和差异报告，另行决定是否重放；不得覆盖旧实验结论。
