## 以后加新东西的规矩

1. **收想法**：你写“给谁用、解决什么、怎么知道做好了”；先进入下面的候选区，不自动开工。
2. **建工单**：Claude 先查是否重复，再挂到三条主线之一，写范围、优先次序、依赖、验收标准和是否排期；被取代的旧单只保留记录。
3. **记决定**：涉及新规则、数据边界、付费、通知、导航或上线取舍时，先写 ADR（决定记录），由你决定；纯实现细节不重复审批。
4. **发任务卡**：Claude 写 `tasks/NNN-*.md`，限定允许改的文件、数据和检查；Codex 执行并报告疑点。计划本身不授权其他任务。
5. **验收再关单**：Claude 技术验收，你做用户验收；分别记录本地完成、已合并、已部署、实际可用，不能只凭推送代码说上线。

### 在 App 放哪里

- 导航固定最多 **5 个标签 + 更多**：今日、3W 机会、我的组合、成绩单、学习；更多里放研究档案等低频入口。
- 每日需要看的一句话或行动提示，先放“今日”的卡片，详情链接到已有页面。
- 历史报告、未采用的策略、详细研究方法放“研究档案”，不把负结果删掉。
- 只有新的高频核心任务才考虑新标签；已满 5 个时必须决定合并或替换哪个，不能不断加入口。热门股形态默认候选卡片/更多，不恢复第六个主标签。

### 数据约定

- 每页只读一份小 JSON，由 GitHub 自动生成；每份未压缩 **< 2 MB**，包含 `schema_version`、生成时间 `generated_at`、数据日期 `as_of` 和来源。
- 字段含义变化要更新版本并兼容旧页面；无数据与数值 0 分开，过期数据明示日期；不让页面另算一份交易规则，不公开原始价格下载。
- 任务 015 曾允许组合页读两份文件，与本次“一页一份”目标不同；后续阶段 A 卡片应写明如何合并页面数据，本次不改代码。
- 新研究先在账本登记问题、数据、费用、唯一判定，再开卡；新策略检验只能用未使用过且获授权的数据，不能把旧数据换名当新考试。
- 美股 1985—2004 和港股 A 组已考过；港股 B 组及港股 2005 年以前仍锁定。冻结的 3w-1.9 不改；历史描述与新策略验证分开，不因候选区有想法就解锁数据。
