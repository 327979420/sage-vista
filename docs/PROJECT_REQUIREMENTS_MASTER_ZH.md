# Sage Vista 项目总需求

版本：`0.3.0-draft`

整理日期：2026-08-30

状态：跨对话需求总档；用于说明用户究竟想把 Sage Vista 做成什么。它不是生产状态证明，也不会自动改变评分、扫描、回测、网站或 Discord。

## 内容分类

- `正式需求`：用户已经确认的产品目的、边界和不可破坏原则，可以进入正式正文，但仍不等于代码已经实现。
- `候选设计`／`候选实验`：用户希望保留、但尚未批准生产实施或尚未得到证据的想法。
- `历史快照`：带日期、版本、数量、股票或收益的当时记录，只用于追溯，不能代替当前状态。
- `当前机器状态`：本文件不手抄；统一引用`docs/CURRENT_STATUS_ZH.md`及其列出的JSON和Git来源。

需求是否确认、是否批准实施、是否已经上线，统一以`docs/DECISION_LOG_ZH.md`的“三种状态的唯一说明”为准。本文件不另建状态表。

## 这份文件从哪里来

本文件综合核对了编号 1—6 的 Sage Vista 相关任务。第 5 阶段在应用中存在“主策略对齐”和“5.1 实施／回测”两个任务，二者视为同一阶段的主任务与分支；同时核对了它们引用的 ChatGPT 过渡对话。

整理时遵守四条规则：

1. 用户最后明确确认的决定，标记为“当前目标”。
2. 用户提出但尚未验证的想法，标记为“候选实验”，不能写成有效规则。
3. 旧版本曾经使用、后来被替代的内容，保留为“历史”，不能删除或冒充当前规则。
4. 聊天中声称“做完”的内容，必须能在 Git、机器产物或生产站点中核验，才能标记为已实现。

## 一句话宗旨

> Sage Vista 要把用户的交易经验变成可解释、可复查、可回测、可持续升级的选股与模拟决策系统：每天先找到值得人工看的股票，永久保存当时证据和交易计划，再用历史与真实前向结果持续纠错。

它不是自动下单系统，也不能把“因子命中数”冒充胜率。

## 用户最终想得到什么

1. 一个每天能可靠更新的美股选股器。
2. 一个复杂多因子模式：找因子颗数多、家族覆盖广、日周月共振强的机会。
3. 一个简单个人模式：找用户最喜欢的回调、底部、突破和承接形态。
4. 每个可交易候选都给出入场、止损、自然目标、风险收益比、预期持有时间和失效条件。
5. 大盘和行业作为独立环境判断，帮助调整优先级和风险，但不伪装成技术因子。
6. 一盘能够重复使用的历史录像，用来研究最高共振、最大赢家、最大输家、漏检赢家和误收输家。
7. 机器先解释，用户逐根 K 线人工复核；用户可以否决机器，但不能改写机器当时的原始判断。
8. 网站只展示每天真正能用的结果，复杂实验和历史明细留在 Git 后台。
9. 所有经验、失败、规则版本、实验和人工案例都能被后续对话继续使用。

## 一、六阶段项目演变

### 阶段 1：从技术选股器开始

最初目标是建立一个私有、专业的美股技术选股网站。核心要求已经包括：

- 多个指标说明同一件事时才考虑入场；
- 大周期确认方向，小周期寻找时机；
- 支撑、阻力、供需、期权墙和 measured move 用来讨论止损止盈；
- 输出入场、止损、持有时间和仓位；
- 入场后长时间不动就退出；
- 扩大股票和历史样本，避免只看少量幸存股票；
- 学习成熟开源量化架构，但不能把别人的策略直接当作本项目结论。

这一阶段的重要纠错：网页必须是中文、人话、可点开核验；排行榜要稳定，不能只给机器结论。

### 阶段 2：MACD 门票与多因子研究

项目逐渐冻结为：长期趋势／回调背景下，由日线 MACD 金叉提供候选时机，再研究双底、三推突破、RSI 背离、Doji、看涨吞没、成交量、Fibonacci、EMA、FVG、跳空、周月线等附加证据。

用户要求：

- 覆盖 2000 年以来历史并尽量包含退市股票；
- 日线主要看 20 个交易日，长期研究可看 60—100 日；
- 周线、月线只能使用当时已经完成的 K 线；
- 失败因子也要留档；
- 研究页面用曲线、图表和人话结论，不堆术语；
- 研究详情和生产机会必须分开。

这一阶段的重要纠错：不能因为五六分样本看起来漂亮，就把小样本包装成已验证买入信号。

### 阶段 3：统一因子库、自动更新和 Discord

固定六因子逐渐扩展成可版本化因子库。用户要求保留 RSI、背离、成交量、EMA、Fibonacci、FVG、趋势线和形态检测能力，即使删除它们的旧独立页面。

同时确立：

- 因子要有稳定 ID、版本、机器定义、研究状态、时效状态和重复关系；
- 监测一个因子不等于给它正式权重；
- 日终必须先更新数据，再测试、防前视、发布网站，最后才发送 Discord；
- 数据日期不一致、测试失败或网站未验证时必须停止发布和通知；
- 网站与 Discord 使用同一结果，不能各算一套。

这一阶段的重要纠错：自动任务“运行成功”不等于网站已经更新；数据、提交、部署、线上核验和通知必须分别证明。

### 阶段 4：行业雷达、永久信号账和产品收敛

Industry Radar 被定义成和个股技术检测分开的环境层。ETF 成分、行业分类和价格必须有可审计来源；无法映射的数据标记 unavailable，不能猜。

同时建立三个不同概念：

- Current：今天看什么；
- Forward／Signal History：系统当时真实提醒了什么，后来怎样；
- Backtest／Research：历史规则在受控实验中会产生什么。

这一阶段的重要纠错：旧 Tracker 历史候选不能被重新命名成当前多因子回测；今日榜、真实前向和历史回测不能混在同一个表里。

### 阶段 5：重新确认多因子主线并暴露工程问题

用户发现项目从“可用选股系统”偏成了“实验页面集合”。PG 的首次高分与后来零正式分暴露了评分语义、今日状态和历史信号混淆。

用户重新确认：

- 主线是多因子选股与策略优化；
- 历史高分和真实触发必须冻结，不能因今天掉分而消失；
- 行业和大盘服务于个股决策，不应各自长成互相竞争的产品；
- 所有回测必须分段保存和断点续跑；
- 新增一个因子时，只补算新因子或受影响部分，不能无理由重跑全部二十多年数据；
- 结果必须更新成用户能看到、能核验、能使用的页面结论。

这一阶段的重要纠错：不能花很久只生成一堆汇总数字；不能重复报告“因子没用”；每轮实验都要有具体股票案例让用户人工复查。

### 阶段 6：架构优先、两种模型和人工复盘闭环

当前阶段不再继续堆功能，而是先把项目拆成可复用模块。复杂多因子和“我最喜欢形态”共用一份行情、一个日线 MACD 门票和一个回调结构预检，然后分别判断。

回测的任务也被重新定义：它不是为了反复生成数字，而是为了持续找到机器最成功、最失败和最容易漏掉的案例，交给用户人工复核，再形成可检验的新假设。

本阶段最新一轮人工复盘进一步确认：局部因子之前必须先理解股票所处的长期结构。DLTR说明多年反复向下跳空不能被一个普通风险标签带过；BTDR说明宽幅箱体内部的金叉和吞没不能冒充趋势突破；MRNA说明系统必须接受“主动错过后来大涨但长期结构已破坏的股票”；CGEM说明长期下跌后若经历足够长的底部消化，并由月线转变和日线重新启动共同确认，可能形成一条不同于传统长期上涨回调的候选资格路径。以上均先进入总需求和案例账，不直接改变生产规则。

## 二、目标架构：三条链，不再混成一条

### A. 每日生产链

```text
准备一次行情
→ 大盘和行业 ETF 每天算一次并缓存
→ 全市场只做一次门票和结构预检
→ 建立唯一候选池
→ 复杂多因子与我最喜欢形态分别检查
→ 加入独立的大盘／行业／风险意见
→ 判断是否达到交易标准
→ 建立模拟交易计划
→ 写入唯一事件账
→ 网站展示
→ 线上核验通过后 Discord 提醒
```

### B. 历史回测与实验链

```text
读取同一份历史行情录像
→ 按历史每一天当时可见的信息重放每日检查
→ 复用同一检测器和同一事件定义
→ 保存事件编号、冻结证据和后续价格路径
→ 用不同实验规则读取同一批事件
→ 输出总体结果和具体案例
```

### C. 人工复盘与升级链

```text
机器挑选最高共振／最大赢家／最大输家／矛盾案例
→ 机器解释当时已知证据与风险
→ 用户逐根 K 线复核
→ 保存机器原判断和人工意见
→ 形成后验候选假设
→ 新实验预登记并做全样本对照
→ 用户批准后创建新规则版本
→ 从下一交易日进入生产
```

人工复盘不是回填历史答案，也不能直接改变原实验。

## 三、数据只保存一次

把历史行情想成一盘录像：

- 行情仓：只保存一份可复用价格历史；
- 事件大档：每个历史日期／股票事件只保存一次冻结事实；
- 实验：保存使用了哪些事件、规则、结果和结论，不复制整盘行情；
- 人工复盘：挂在事件编号下面，不复制另一份事件；
- 网站：只读取今日和少量摘要，不下载整个研究仓库。

只有门票、股票池、价格定义或点时检测规则发生改变时，才重放受影响的历史。新增普通附加因子时，应优先只补算该因子。

## 四、股票池与扫描优先级

### 每日扫描

优先检查交易量、市值和关注度较高的股票，再逐步扩展到更小股票。具体 universe 版本必须保存，不能把“当前热门股名单”伪装成历史股票池。

### 历史回放

按以下层级逐步扩大并分别报告覆盖率：

1. 核心热门池；
2. 主扫描池；
3. 拓展池；
4. 更小股票；
5. 退市／将退市股票。

每一层都能断点续跑，不能因后续增加股票而丢弃已经完成的周档。

## 五、共同门票与结构闸门

### 日线 MACD 门票

- 当前两个选股模式共用完整日线 MACD 刚金叉候选池。
- 门票只决定是否继续深查，不代表可以买入。
- 改变门票会改变事件池，必须单独立项和重放历史。

### 深度回调

- 回撤比例使用前一段已确认上涨波段计算，不是简单的“股价从最高点跌了多少”。
- 回撤超过 70%，且最新完整收盘仍未站回 0.618 回撤价位：`structure_broken`，停止重因子检查，但保存紧凑排除记录。
- 回撤超过 70%但重新站回 0.618：`deep_sweep_reclaimed`，继续检查并显示深插风险。
- 0.618—0.70 是深回调警告，不自动加分。

### 先判断长期结构和股性，再解释局部因子

共同门票和深度回调之后，系统必须能够把候选至少解释成以下四类；在机器定义和对照实验完成前，允许显示“待人工判断”，不能由代码猜：

1. **长期上涨后的健康回调**：当前主策略最优先的背景。
2. **长期筑底后客观转变**：长期下跌已经由一年以上底部消化、多次拒绝新低、完整月线转强和日线重新启动共同改变；CGEM是已见验收案例。这是候选资格路径，不是当前已批准生产门票。
3. **长期宽幅箱体**：局部MACD、吞没、Fibonacci和放量可能只是区间内反弹；没有完整收盘脱离冻结箱体前，不得解释成趋势突破。BTDR是已见反例。
4. **长期结构破坏／深跌反弹**：即使局部EMA和MACD转强、后来大涨，也可以是系统有意放弃的机会；MRNA是已见验收案例。

同时单列持续供给故事：DLTR式“多轮向下跳空→回补失败／刚回补又出现新缺口→最近关键缺口仍未收复”不能压缩成一个无影响排名的布尔提示。机器第一步应保存次数、日期、回补状态和最近一次控制权；它最终是降低排名、减少头寸还是硬否决，必须做匹配对照后决定，不能根据一个案例直接扣分。

## 六、两种选股模式

### 1. 复杂多因子

目的：回答“今天哪些股票出现了最多、最广、最一致的技术共振”。

当前目标家族：

1. 方向／背景；
2. 可控回调；
3. 支撑／位置；
4. 重新启动；
5. 风险／供给。

EMA、MACD、RSI、成交量、FVG、K 线、双底、三底和趋势线等是证据来源。页面同时显示：

- 原始命中颗数；
- 覆盖家族数；
- 同家族的二次确认；
- 日、周、月周期共振；
- 未命中的重要条件；
- 风险和供给证据。

同一种故事不能伪装成很多个独立家族；但同家族重复确认可以作为“共振强度”单独展示。是否加权、加多少，必须由回测和新版本决定。

#### 二次独立三推确认（已登记待办，架构重整后提醒）

- ADBE 2023暴露了一种需要长期保留的结构：第一次W底／三推突破完成后，价格经历真实回调和动能重置，又使用一套全新的下降高点完成第二次三推突破。
- 它进入复杂多因子，不作为“我最喜欢形态”的第五个必选条件；在因子库中和“三推趋势线突破、三推突破后回踩、W底颈线回踩”放在同一价格结构／重新启动家族并使用同一颜色。
- 第二次三推必须发生在第一次突破后的真实重置之后，且三组高点全部是新的已确认pivot；不能重复使用第一段高点，也不能把普通颈线突破冒充第二次三推。
- 同一股票日期仍只建立一个事件和一笔模拟交易。两次三推分别保存证据；家族覆盖只算一个，但可登记同家族父子`double_confirmation`。
- 第一版只作为研究证据进入多因子人工复核排行，正式权重为0。它是否稳定提高胜率、收益、PF或交易期望，必须另做全样本对照；ADBE只能验收检测器，不能证明有效。
- 2026-08-30需求确认记录是先完成总体架构重整，不立即加入因子库（`历史快照`；来源为CR-2026-08-30-033）。等重整进入“复杂多因子检测／因子库重建”阶段时，必须主动提醒用户重新审查并决定是否实施；在此之前不得悄悄增加第40项因子或改变排行。

#### 复杂多因子的两种周期路径（新增目标，待实验）

复杂多因子不能再把所有“日／周／月共振”压缩成同一种主导周期标签。用户希望同时研究两条不同的时间路径：

1. **大周期确认型（大→小）**：在日线入场信号出现以前，完整月线已经给出长期方向，完整周线已经给出中期阶段，日线突破只负责具体择时。这类交易仍按日线突破管理，第一轮研究最长持仓约20—30个交易日，不因为月线存在就强迫长期持有。
2. **小周期升级型（小→大）**：日线先启动；只有长期结构没有破坏、月线没有明确空头、周线也没有明确空头时，才可以先按日线短计划入场。周／月周期可以暂时中性，但任何一个明确空头都阻断完整交易。之后新的完整周线、完整月线逐级确认，说明原本的日线行情可能正在成长为更大周期趋势，才允许研究把最长持仓逐级延长。

第二条路径必须按时间顺序保存确认过程，不能在最初日线入场时偷看后来才完成的周线或月线：

```text
日线信号先建立短周期交易计划
→ 持仓仍有效时，完整周线后来确认
→ 从周线确认日起获得“可延长”资格
→ 持仓仍有效时，完整月线后来确认
→ 从月线确认日起再获得更长观察资格
```

如果周线／月线确认发生在原交易已经止损、止盈、失效或按原计划退出之后，它不能倒过来延长旧交易；需要按新事件或再入场候选处理。持仓延长只是最大允许窗口，不覆盖结构止损、自然目标、已批准退出条件和硬风险。

每一级周线或月线确认必须同时满足：该周期至少两个独立证据家族，其中至少一个属于方向、价格结构或重新启动。只有接近一条EMA、单一支撑距离或一个尚未确认的形态不够。确认只能在该周期K线完整收盘后成立，持仓升级最早从下一可执行时点生效。

持仓上限统一从最初入场日计算，不在周线或月线确认日重新计时；半年统一按约126个交易日研究。第一轮不因周期升级自动加仓，只延长剩余仓位的最大允许持仓。

第一轮阶段上限冻结为：日线初始计划最多30个交易日；完整周线必须在入场后30个交易日内确认，确认后上限提高到60日；完整月线必须在当时所处的60日上限内确认，确认后上限提高到126日。100日只作研究敏感度，不是独立生产阶段。超过当时阶段期限才出现的确认不延长旧交易。

小周期升级型若在交易仍有效时完成至少一次高周期升级，之后达到2R时卖出90%，只留下10%长期仓继续跟踪。若尚未完成任何升级就先达到2R，仍按原日线短计划完整退出，不能事后复活10%仓位。

剩余10%仓位出现至少两个独立日线退出信号时，在下一可执行时点全部退出。退出信号必须按家族去重；父子信号、同义代理或同一根K线描述同一风险时不能凑成两个。候选清单包括看跌吞没及跟随、RSI三峰背离、MACD正柱衰减、异常放量大阴线和EMA50动态支撑失守；精确计数与保护止损仍须在执行模块冻结。

未来实验的第一候选保护方式冻结为：保留原结构止损；2R部分止盈后，对剩余10%同时启用“此前最高完整收盘价下方8%”追踪和两个独立日线退出家族，任何一个先触发就先退出。看跌吞没及其随后阴线属于同一风险故事，只算一个家族，不能仅靠父子信号凑够两个。

已经建立或升级的交易，如果相应周线或月线后来出现至少两个独立空头证据家族，则在确认后的下一交易日退出全部剩余仓位。高周期退出与日线双信号退出、价格止损、硬风险同时存在时，执行最早触发者。

以上两种周期路径、30→60→126日延长、2R卖出90%留10%、8%追踪、日线双退出和高周期双空头退出，在2026-08-30需求记录中全部属于**未来实验方案**（`历史快照`；来源为CR-2026-08-30-036）。生产默认不启用，不修改现行持仓、止损、止盈或退出。它们在重构阶段只需要有可扩展的数据位置，等用户以后批准独立预登记和回测后才实现行为。

若价格在某交易日盘中先按旧计划完整触及2R，而周线／月线确认只能在该日收盘后才知道，则旧计划优先，不能在收盘后倒回去保留仓位。只有升级在此前已经生效，2R部分止盈规则才适用。

两条路径都属于复杂多因子，不改变“我最喜欢形态”的四项定义。页面必须显示路径、各周期确认日期、当前升级阶段和当前最长观察窗，不能只显示模糊的“多周期共振”。具体分值、升级条件、持仓起算点以及“半年”按交易日还是日历日计算，必须预登记后再冻结。

#### 复杂多因子达到交易标准（候选目标 V0，非生产状态）

必须同时满足：

1. 通过共同门票和结构闸门；
2. 长期方向没有明确破坏；
3. 可控回调家族命中；
4. 支撑／位置家族命中；
5. 重新启动家族命中；
6. 没有已批准的硬风险否决；
7. 能定义入场、支撑、止损和自然目标；
8. 到自然目标至少有 `1.5R` 空间。

只有“因子很多”但没有位置、启动或可执行交易地图，不算达到交易标准。

### 2. 我最喜欢形态

目的：用更简单的形态语言，找用户愿意优先人工查看的机会。

当前目标为严格四项：

1. 有真实回调；
2. 形成客观双底或三底；
3. 完整日 K 收盘完成三推下降趋势线突破；
4. 回调获得 Golden Pocket 或 EMA20／50／200 承接。

四项齐全后仍需：

- 通过风险闸门；
- 有有效入场、支撑、止损和自然目标；
- 自然目标至少 `1.5R`。

“W 底突破后回踩颈线”和“三推突破后回踩”属于可研究的突破回踩家族；在单独冻结前，不应偷偷替换当前四项定义。

#### BABA提供的完整人话模板

BABA是用户个人形态语言的教学案例，不是要求所有股票复制同一张图。它保存的完整判断顺序是：

```text
日线先出现一段可解释的转强和上涨
→ 上涨后回调到约0.618 Golden Pocket或EMA200
→ EMA200附近形成双底／三底承接
→ 第二底附近出现日线MACD金叉
→ 下降趋势线完成三推并由完整收盘突破
→ EMA20重新站上EMA50，均线关系恢复多头
→ 突破时考虑入场，先看此前高点作为自然目标
```

用户原始观察中特别强调：BABA当时未必符合传统多年长期上涨，但日线已经先完成一段客观趋势转变；因此“背景成立”不能简单等同于股票过去一直上涨。具体日期、价格、0.618波段和均线数值仍需统一复权行情核验；在核验前，案例只负责保存交易语言和检测器验收，不参与收益证明。

## 七、大盘与行业

### 计算顺序

- SPY、QQQ、IWM、RSP和行业 ETF 每天先计算一次并缓存；
- 同行业股票复用同一份行业状态；
- 它们在个股技术检查完成后参与最终优先级和风险判断；
- 不混入技术原始分后再宣称技术评分有效。

### 两个方向的行业共振

1. 自上而下：行业 ETF 的趋势、回调、支撑、修复、成交量和相对强弱是否支持个股。
2. 自下而上：当天多个行业成员是否同时出现相似技术信号，反推行业可能正在启动。

计算某只股票的行业广度时应排除它自己，并且行业只计算一次，防止“六只金融股让金融变热，金融又反复给六只股票加分”的循环。

### 热度

资金流、成交量、成交额和话题讨论度分别保存。讨论多可能代表热钱，也可能代表过热，因此第一版只用于同分或相近技术候选的排序提示，不能直接当作看涨因子。

行业／大盘是否改变仓位、持仓时间或风险上限，必须分别实验。

## 八、模拟交易与退出

### 基本交易计划

每个完整计划至少保存：

- 信号日；
- 计划入场日和价格口径；
- 冻结支撑；
- 结构止损；
- 最大风险上限；
- 自然目标；
- 目标对应的 R 倍数；
- 预期持有周期；
- 复杂多因子的周期路径：大周期确认型／小周期升级型／尚未分类；
- 日、周、月各自的确认日期与当前持仓升级阶段；
- 当前最长允许持仓及其生效日期；
- 时间失效和提前退出规则版本。

信号在完整收盘后产生，历史模拟默认下一交易日复权开盘入场。

### 当前风险方向

- 用户倾向以支撑下方作为结构止损，并研究约 5% buffer 和最大计划亏损 10%；精确参数必须绑定实验／执行版本。
- 固定支撑止损、`+1R` 后最高收盘下 8% 追踪、ATR 止损必须作为不同策略对照，不能混成一条回测后再归因给因子。
- 自然目标不足 `1.5R` 时不建立完整交易。

### 时间退出

“我最喜欢形态”先单独实验：从实际模拟入场起 20 个完整交易日内，如果从未有收盘收益达到 `+5%`，或第 20 日已经收回冻结盘整区，则下一交易日开盘退出。

复杂多因子是否采用相同时间退出，另做实验。

复杂多因子的周期路径必须另开持仓实验：

- 大周期确认型先比较20日与30日，不因大周期方向存在就默认延长；
- 小周期升级型冻结“日线30日→30日内周线确认后60日→60日内月线确认后126日”；100日只作敏感度；
- 所有最大持仓都从最初入场日计算；从升级确认日重新计时只允许作为研究敏感度，不得冒充主结果；
- 比较固定短持有与逐级延长时，入场、止损、目标、成本和股票池保持相同；
- 至少完成一次升级后达到2R卖出90%、留下10%；剩余仓位出现两个独立日线退出信号，或高周期出现两个独立空头家族时退出；
- 任何止损、目标、结构失效、风险否决或已批准主动退出仍优先。

### 提前退出候选

以下暂时属于独立候选实验，不是已经全部投入生产的综合退出系统：

- 实体看跌吞没；
- 看跌吞没后的阴线 follow-through；
- RSI 连续三峰看跌背离；
- MACD 多头柱持续衰减；
- 异常放量的大实体阴线；
- EMA50 动态支撑明确失守且未修复。

必须分别测试单项帮助多少、伤害多少，再决定是否组合。

## 十、回测到底用来做什么

回测不是为了交一张总体胜率表。它固定追踪：

1. 因子命中数最多；
2. 家族覆盖最多；
3. 多周期共振最强；
4. 按冻结模拟执行实际盈利最多；
5. 按冻结模拟执行实际亏损最多；
6. 因子很多却大亏；
7. 因子很少却大赚；
8. 被门槛淘汰后却大涨；
9. 接近门槛的边界案例。

人工复盘必须进一步把案例分成四种，不能只分赢家和输家：

1. **机器抓对且人工认可**：例如CGEM式候选，但仍要审计机器是否入场过早；
2. **机器高排但人工拒绝**：例如DLTR、BTDR，寻找机器漏掉的风险或状态；
3. **后来上涨但系统应主动放弃**：例如MRNA，不能把有纪律的漏过错误写成排序失败；
4. **机器信号与人工入场不是同一天**：分别计算早期门票入场和完整形态确认入场，不能用后来的K线美化早期信号。

原始 20 日收益与带止损／止盈的交易盈亏必须分开。最大赢家／输家必须按同一冻结执行规则选取。

每轮实验至少交付：

- 总体和分期结果；
- 一个规则明显帮助的案例；
- 一个规则明显伤害的案例；
- 一个边界／漏检案例；
- 机器当时已经知道什么；
- 人工可以逐根 K 线核验的日期、入场、支撑、止损、目标和退出。

每张案例卡必须保留三条互不覆盖的结论：机器当日真实知道什么、用户后来怎样解释、这些差异是否只产生新实验假设。人工意见权重大于机器的最终交易决定，但不得重写机器原分数、原排名、原信号日或当时尚未完成的周／月K线。

## 十一、实验与规则升级

### 固定研究分期

- 2000：指标和均线预热；
- 2001—2024：开发；
- 2025：独立验证；
- 2026：前向观察。

新增股票池或退市数据时，单独报告实际覆盖，不把今天的股票名单回填过去。

### 因子归因

- 比较命中与未命中，而不是只统计赢家出现次数；
- 同时比较全候选、赢家、高收益、失败样本中的基础出现率；
- 排序同时看样本、跨期方向、胜率增量、PF、期望、中位收益和年份分散；
- 外部高口碑、成熟开源量化项目只能作为定义和显示顺序的辅助先验，不能替代本项目证据。

### 防止伪结论

- 同一股票重叠事件去重并做全事件敏感度分析；
- 极端赢家不能代替全样本；
- 多重比较必须冻结候选和数量；
- 组合必须优于总体和组成它的单因子；
- 已看过的案例只能用于验收，不进入收益证明；
- 每次判断只使用当时已完成的日／周／月数据和当时有效分类。

### 从实验进入生产

```text
提出问题
→ 写清目的、假设、基线和失败条件
→ 预登记
→ 运行并保存所有结果
→ 机器案例解释
→ 用户人工复核
→ 形成结论
→ 单独提出生产变更 CR
→ 用户批准
→ 新版本从下一交易日启用
```

实验不能自动调低或提高因子权重，旧历史也不能被新规则重写。

1. 新想法先记录，不直接写代码。

### 候选设计：需求文字闭环闸门（CR-2026-08-30-037，`design_review`）

以下原始要求完整保留，等待CR-2026-08-30-037正式批准；当前不能把`requirements_closed`写成已经生效的仓库状态。候选规则为：代码可能比文字复杂，但不能比文字多出未经批准的业务决定。一个模块只有在文字上同时回答完下面问题，才算`requirements_closed`，才允许进入代码设计与实施：

1. **为什么做**：用户要解决什么问题，成功后实际能做什么；
2. **从哪里开始**：唯一输入、数据日期、点时边界、前置资格和触发条件；
3. **正常怎样走**：按时间顺序写出完整主流程和状态变化；
4. **什么会停止**：淘汰、风险阻断、数据不足、退出和失效条件；
5. **冲突听谁的**：门票、长期状态、技术证据、大盘行业、人工判断、止损退出和硬规则的优先顺序；
6. **结果写到哪里**：唯一输出、唯一负责人、事件ID、网站和Discord消费者；
7. **特殊情况怎么办**：同一股票命中两个模型、同日重复信号、持仓中再次触发、周期后来升级、确认发生在退出以后、缺失周月数据等；
8. **什么时候生效**：完整日／周／月K确认时点、下一可执行价格、版本启用日和旧历史冻结方式；
9. **怎样证明没有改坏**：自动测试、成功案例、失败案例、边界案例、新旧对照和防前视检查；
10. **失败怎样退回**：回退点、旧入口保留期、迁移失败和半套数据的处理方式。

仍未决定的问题必须明确列在模块的“暂不实施”区。不能一边把问题写成待定，一边让代码选择一个默认答案进入生产。用户在文字上确认完整模块设计以后，才开始该模块第一个不超过20分钟的实现包。

文字闭环不等于必须现在决定所有未来实验。对尚未验证的想法，只要明确写成“当前不实施、生产保持原样、未来另开实验”，当前模块就可以闭环；代码只能预留稳定接口，不能预先启用实验行为。

### 下一阶段：在新对话中分模块重整代码

用户下一阶段将新开对话，依据本总需求逐个板块重整实现。目标是重新建立清楚、可读、可删除旧代码的项目结构，而不是在现有复杂链路上继续堆补丁。

执行顺序固定为：

1. 新对话先读接手入口、当前状态、本总需求和架构图；
2. 先列出每个功能的唯一负责人、输入、输出和当前调用者；
3. 把现有文件标成`保留／重写／迁移后退休／历史只读`，文件年龄不能单独决定删除；
4. 一次只选一个板块，先交架构接入设计和不改变范围；
5. 用户批准后，先更新该模块规则，再用不超过20分钟的小包重写并做新旧输出对照；
6. 新入口稳定、历史可复现、页面和自动化都已迁移后，旧实现才允许退休；
7. 所有新增或重写代码必须有人话注释和最短阅读路径；
8. 不进行一次性“大爆炸重写”，不在同一包里同时改门票、因子、评分、执行、账本和页面。

代码瘦身的验收不是“文件变少”，而是：一份行情、一个门卫、一个候选池、两个独立选股器、一个风险执行层、一本正式总账、四个日常页面和一个验证后的Discord出口，各自只有一个权威实现。

## 十四、用户反复否定过的做法

以下内容不是语气记录，而是明确的产品禁区：

- 只给一堆数字，不告诉用户具体怎么用；
- 实验完成后反复说同一个负结论，不提出下一步建设性对照；
- 回测没有具体股票、日期、因子和交易地图，无法人工复查；
- 声称几分钟跑完多年／几十个因子，却不解释复用了什么、真正计算了什么；
- 每加一个因子就从零下载和扫描二十多年行情；
- 长任务只在最后保存，一旦超时全部白做；
- 网站仍显示旧数据、旧排行榜或旧结论，却声称已经更新；
- 研究页、今日榜和 Discord 各自使用不同排名；
- 用今天的分类、后来确认的底部或未来 K 线解释历史；
- 让大盘／行业污染技术分，再宣称技术评分有效；
- 因子、页面、旧实验和兼容代码只增不退，形成无法检查的死代码；
- 未经架构确认就直接修改多个板块；
- 把单一人工案例硬编码成所有股票必须复制的图形；
- 把机器错误藏在总览摘要里，不给用户点进股票人工核验。
